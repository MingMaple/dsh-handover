# dsh-handover

覆盖长任务从立项到归档全过程的上下文治理工作流。DeepSeek Harness（DSH）插件，当前版本 1.1.0。支持 DSH 0.2.1-rc.2 至 0.3.0，不含 0.3.0 及其候选版；准确范围见 `package.json` 的 `engines.dsh`。已在 0.2.2-rc.5 上实测通过。

## 为什么需要

单个会话的上下文越用越多，用到一定程度之后，出错的可能也会随之上升；可若这时压缩上下文，或者写好交接换一个会话，又会丢掉已经积累的信息。面对这样的两难，有没有更好的取舍？

本插件一定能很好地帮助你。来试试吧；不满意，随时关闭插件并删除即可。

## 能做什么

长任务通常会遇到 4 类问题。上下文接近上限时，压缩会损失信息，不压缩则可能出错。更换会话时，交接容易遗漏细节。任务分派、文件布局与版本对齐，也需要统一的处理方式。插件把这 4 类工作收进 6 个工具，按 `action` 或 `view` 分流。

- `ho_status`：水位、体检、自检与原文召回，只读。
- `ho_handover`：交接读写、换任重写、归档与轮内压缩。
- `ho_docmap`：体系注册、计划、骨架、台账与规则正文。
- `ho_sessions`：建会话、设角色、查在任与换任。
- `ho_workspace`：工作区生命周期、根目录搬迁与备份迁移。
- `peer`：平级会话通信，投递、等待与收集结果。

### 上下文与交接

上下文按当前窗口分 3 档：整理线 35%，建议线 50%，强制线 65%。到达整理线或建议线时，插件注入提示。写胶囊时写全目标、已定方案、下一步与需要保留的原文位置。压缩后按胶囊继续，原始细节不丢失。需要原文时按序号回读，不必重读整段历史。到达强制线时，插件自动压缩，不要求先选定断点。

会话接近上限时，还有换任一种方式。重写交接、归档旧件与体检结构由一个动作完成。交接只写在途事项与指针，不写流水账，接任会话读一遍即可继续。换任须由用户授权，篇幅与结构由体检把关，不会自动发生。

### 会话与分派

一键部署全局根之后，会话按角色装配工具与提示段。工具数随角色变化：全局 6 个，项目与杂项各 5 个，普通会话 0 个。项目与杂项可以互转身份。迁移为可选项，缺省不移动文件。

轻量任务直接执行。繁重任务先写计划，写明目标、步骤、验收、风险与状态 5 节。计划写在任务根，收尾时归档，先计划后动工。工作量大时按判据派出子智能体并行处理，主会话负责统筹与收尾。一段工序或整个项目可以交给 DSH 之外的会话，完成后按 3 种方式之一归还。多个插件会话之间可以注册协作，由统筹者派发任务，成员交付，结果统一收回。

### 查询与迁移

水位、压缩计数、闸门与交接体检各有一个只读视图，不必逐个翻文件。设置页提供「对齐检查」：唤醒全局在任会话，按内置标准核对各项目的体系。报告按组列出，先询问需补齐的项，得到选择后才执行。文件体系有固定布局与注册表。库快照附带清单，可以逐项校验。恢复时按清单比对，不一致即中止。跨机器迁移分 3 步：打包、校验清单、预演恢复。全局根目录支持在线搬迁，无需停机。

分档细则、胶囊字段与锚点见[机制说明](docs/mechanics.md)。

## 安装

### 从 GitHub 安装

桌面版在侧栏「插件」中点击「添加插件」，粘贴仓库地址 `https://github.com/MingMaple/dsh-handover`。Web 界面或命令行：

```bash
dsh plugin --profile web add github:MingMaple/dsh-handover
```

### 从 npm 安装

包名为 `@mingmaple/dsh-handover`，版本与仓库同步。从本地源码安装时，先执行 `node scripts/build.mjs`，产物在 `dist/`，再用插件管理器安装该目录并重启 DSH。

```bash
dsh plugin --profile web add @mingmaple/dsh-handover
```

### 首次使用

安装完成后，以下两种方式效果相同。其一，在设置页粘贴目录路径，点击「一键部署」。其二，执行 `ho_workspace(action="init", parent="<全局根上级目录>", register=true)`，再新建一个标题含「全局」的会话。各流程的做法与对话示例见[使用说明](docs/usage.md)。

## 设置页

单页卡片式，常用区展开，低频与长文段折叠。卡片含授权、移动全局根目录、会话角色、全局前置提示词与会话水位。另有通用约束条、交接文档体检与插件信息；末尾为工具明细与使用说明。

页头提供「对齐检查」：唤醒全局在任会话，按插件内置的对齐标准核对各项目。报告按组列出，先询问需补齐的项，得到选择后才执行。没有全局在任会话时只报错，不代为新建会话。

## 边界与限制

- 压缩依赖 DSH 的 `ctx.compaction` 服务；未挂载时压缩相关工具报错。
- `ptc` 呈现模式下，插件工具只能经程序调用。
- 会话水位依赖宿主保存的会话状态文件布局；字段变化时用 `ho_status` 的 diag 视图排查。
- 项目名不超过 24 个字符，任务名不超过 40 个字符；名字不含路径分隔符与控制字符。
- 插件重载后，已存在的会话沿用旧提示段文本；需要新文本时重启 DSH 或新建会话。
- 服务端是纯 Node ESM，不调用 PowerShell、cmd 或 bash；三平台同一套代码。
- 卸载后残留仅 `~/.dsh/storages/dsh-handover.*` 与日志目录。
- 插件本体不含用户项目、会话或账号数据。

## 开发

源码在 `src/`，`dist/` 为打包产物，不入版本库。打包与校验命令见 `package.json` 的 scripts。替换 `dist/` 后，在插件列表停用再启用即生效；客户端产物不热更新。修改设置页须重建并重启 DSH，否则界面不变。
