# dsh-handover

把长任务从立项做到归档的上下文治理工作流。DeepSeek Harness（DSH）插件，当前版本 1.1.0。支持 DSH 0.2.1-rc.2 至 0.3.0，不含 0.3.0 及其候选版；准确范围见 `package.json` 的 `engines.dsh`。已在 0.2.2-rc.5 上实测通过。

## 为什么需要

单个会话的上下文越用越多，用到一定程度之后，出错的可能也会随之上升；可若这时压缩上下文，或者写好交接换一个会话，又会丢掉已经积累的信息。面对这样的两难，有没有更好的取舍？

本插件一定能很好地帮助你。来试试吧；不满意，随时关闭插件并删除即可。

## 能做什么

一个长任务会反复撞上同一类麻烦。上下文快满了，压缩心疼，不压缩又怕出错。会话要换，交接一写就丢细节。活分给谁、文件怎么摆、新版本来了怎么对齐，也得有人管。插件把这四件事收进 6 个工具，按 `action` 或 `view` 分流。分工如下。

- `ho_status`：水位、体检、自检与原文召回，只读。
- `ho_handover`：交接读写、换任重写、归档与轮内压缩。
- `ho_docmap`：体系注册、计划、骨架、台账与规则正文。
- `ho_sessions`：建会话、设角色、查在任与换任。
- `ho_workspace`：工作区生命周期、根目录搬迁与备份迁移。
- `peer`：平级会话通信，投递、等待与收集结果。

### 上下文与交接

上下文按当前窗口分 3 档。整理线 35%，建议线 50%，强制线 65%，各管一段。到线前先写胶囊，把目标、已定方案、下一步与需要保留的原文位置一次写全。压缩后照着胶囊继续，原始细节没丢。按序号能回读到原话与原文位置，不必重读整段历史。真顶到强制线，插件自己兜底压缩，不要求你先找到断点。

会话快满还有另一条路：换任。重写交接、归档旧件、体检结构，一个动作做完。接任会话读一遍就能续上，因为交接只写在途事项与指针，不写流水账。换任要你授权，篇幅与结构由体检把关。它不会自动发生。

### 会话与分派

一键部署全局根之后，会话按角色装配工具与提示段，工具数随角色变化。全局 6 个，项目与杂项各 5 个，普通会话 0 个。项目与杂项能互转身份，迁移可选，缺省一个文件都不动。

任务轻就直说；繁重的先写计划，写明目标、步骤、验收、风险与状态 5 节。计划写在任务根，收尾归档。先计划，后动工。活够大时按判据派子智能体并行，主会话只做统筹与收尾。一段工序或整个项目也能交给 DSH 之外的会话，做完按三法之一归还。多个插件会话之间可注册协作，统筹者派活，成员交付，统一收结果。

### 查得到，搬得走

水位、压缩计数、闸门、交接体检各有一个只读视图。不必翻文件。设置页有「对齐检查」：唤醒全局在任会话，按内置标准核对各项目的体系。报告按组列出，先问补哪些。问过才动手。文件体系有固定布局与注册表。库快照带清单，能逐项校验。恢复时按清单逐项比对，不一致即中止。跨机器迁移按 3 步走：打包、清单校验、预演恢复。全局根目录可在线搬迁，不停机。

分档细则、胶囊字段与锚点见[机制说明](docs/mechanics.md)。

## 安装

### 从 GitHub 安装

桌面版在侧栏「插件」中点击「添加插件」，粘贴仓库地址 `https://github.com/MingMaple/dsh-handover`。Web 界面或命令行：

```bash
dsh plugin --profile web add github:MingMaple/dsh-handover
```

### 从 npm 安装

包名为 `@mingmaple/dsh-handover`，版本与仓库同步。从本地源码安装先执行 `node scripts/build.mjs`，产物在 `dist/`，用插件管理器安装该目录并重启 DSH。

```bash
dsh plugin --profile web add @mingmaple/dsh-handover
```

### 首次使用

安装完成后两条路任选，二者等价。其一，在设置页粘贴目录路径，点击「一键部署」。其二，执行 `ho_workspace(action="init", parent="<全局根上级目录>", register=true)`，再新建一个标题含「全局」的会话。各流程的做法与对话示例见[使用说明](docs/usage.md)。

## 设置页

单页卡片式，常用区展开，低频与长文段折叠。卡片含授权、移动全局根目录、会话角色、全局前置提示词与会话水位。另有通用约束条闸门、交接文档体检与插件信息；末尾为工具明细与使用说明。

页头有「对齐检查」：唤醒全局在任会话，按插件内置的对齐标准文件核对各项目。报告按组列出，先问补哪些，得到选择后才动手。没有全局在任时只报错，不替用户建会话。

## 写作规范

本仓库文档遵循作者自用的写作规范。该规范属用户数据，不随包分发，本仓库不引用其条款编号。会话提示段只放一行指针，不注入规范正文。

## 边界与限制

- 压缩依赖 DSH 的 `ctx.compaction` 服务；未挂载时压缩相关工具报错。
- `ptc` 呈现模式下，插件工具只能经程序调用。
- 会话水位依赖宿主保存的会话状态文件布局；字段变化时用 `ho_status` 的 diag 视图排查。
- 项目名不超过 24 个字符，任务名不超过 40 个字符；名字不含路径分隔符与控制字符。
- 插件重载后，已存在的会话沿用旧提示段文本；需要新文本时重启 DSH 或新建会话。
- 服务端是纯 Node ESM，不调用 PowerShell、cmd 或 bash；三平台同一套代码。
- 卸载后残留仅 `~/.dsh/storages/dsh-handover.*` 与日志目录。
- 插件本体不含用户项目、会话或账号数据。

## 开发

源码在 `src/`，`dist/` 为构建产物，不入版本库。构建与校验命令见 `package.json` 的 scripts。替换 `dist/` 后，在插件列表停用再启用即生效；客户端产物不热更新。改设置页须重建并重启 DSH，否则界面不会变。
