# dsh-handover

DeepSeek Harness（DSH）插件，用于长会话的上下文水位管理、交接文档、行动计划与体系注册。插件只使用宿主公开的扩展点，不改动 DSH 本体。

当前版本 1.2.0。支持 DSH 0.2.1-rc.2 至 0.3.0，不含 0.3.0 及其候选版；准确范围见 `package.json` 的 `engines.dsh`。

## 为什么需要

单个会话的上下文越用越多，用到一定程度之后，出错的可能也会随之上升；可若这时压缩上下文，或者写好交接换一个会话，又会丢掉已经积累的信息。面对这样的两难，有没有更好的取舍？

本插件一定能很好地帮助你。来试试吧；不满意，随时关闭插件并删除即可。

## 核心机制

### 任务流程

层级一为轻量任务：单文件修改、局部改名、语法修复、格式化与内容读取。此类任务直接执行，不写计划，不做查证。

用户说「讨论一下」，或助手已就流程询问过用户时，执行前须再确认。用户明确说「直接做」的除外。

层级二为繁重任务：新增功能、多文件联动、重构、架构或接口变更。按以下顺序执行。

1. 先判断纯窗口是否可能超过 40%，当前占用不计入。
2. 在任务根写 `PLAN.md`。超过 40% 时，计划里安排拆子智能体，助手只做统筹与收尾；没超过就按自行完成来写。写完回看上下文核对。
3. 子智能体按成本使用。单个子智能体自身亦需十余步，结论还要回读。只有同时满足以下条件才派：单块 ≥15 步或需读 ≥10 个文件；确需隔离；结果能机械验收。并发 ≤3。能写成脚本再抽检的，先写脚本。派几个、每个多少步写进计划，随计划确认。同一批文件的下一道工序交回原作者续用（`send_message`），不另开。细则见 Charter §十一 与运行时手册 §12.4。
4. 发现缺口时给出方案询问用户；优劣不明时并列全部方案。
5. 用户确认后执行。

子智能体提示词由助手放入规范文件地址与体系说明；插件不向其上下文注入内容。

余量不足时先压缩或办理换任。压缩后按胶囊继续；换任后按「先读交接、再读计划、后执行」恢复。

### 上下文与压缩

上下文按 token 分档：整理线 soft、建议线 advise、强制线 hard。分档按窗口纯比例：整理线 35%、建议线 50%、强制线 65%。三者均为可用窗口比例，不设绝对上限。可用窗口 = 窗口 − 预留输出 13K。200K 窗实得 65K/94K/122K，1M 窗约 345K/494K/642K。窗口读不到时退回绝对预算 80K/120K/180K。

每轮开始时追加一行压力画像：水位、余量、近 3 轮增速与 3 档线。整理线与建议线只注入提示。到建议线后，先把任务收到安全断点，再按胶囊标准写。胶囊含 6 项：目标、已定方案、下一步、易错点、必须遵守的约束原文、需要保留的原文位置。写好后调用 `ho_handover(action="compact", capsule=…)`。强制线由插件机制兜底压缩。提示在同一会话同一档位只注入一次，压缩成功后重置。宿主压缩引擎保持默认阈值 0.8，只作兜底观测，插件不改宿主阈值。

压缩前写会话锚点：`<会话目录>/dsh-handover/anchor.md`，含目标、约束原文、已确认事实与指针、未完成与下一步。压缩后注入胶囊。助手自述胶囊保留正文原样，只加压缩前后 token、缩减比、次序与锚点召回提示。机制兜底胶囊含目标、约束逐条原文、已确认事实与指针、未完成与下一步。助手胶囊与 DSH 摘要互补，不读旧交接全文。锚点与胶囊超限只提示，不裁剪；交接只在更替会话时使用。

微观层由事件触发微快照：工具失败、文件写入、计划或待办变更。6 项为目标、已确认事实、未决、下一步、指针、时刻；条目须可核对，引路径不抄原文，缺项写「未核，待确认」。快照、回填记录与提示状态存放在会话目录内 `dsh-handover/`，会话目录被删除时随之消失。

宏观重置的 4 条保留为追加提示理由。前三条为：累计遮蔽不少于 2 倍窗口；压缩增量比低于 0.5；同错或同文件重复不少于 2 次。第四条为里程碑或用户要求。

每次压缩成功计数加一，助手触发与强制压缩都计。助手入口与到线提示在 4 次后关闭，强制线兜底至 6 次，此后只办理更替会话。换任由 `ho_handover(action="rotate", text=…)` 一步完成归档、写入与体检；承接项由工具返回，需自行并入新正文。用户授权后调用 `ho_sessions(action="succeed")`。宿主没有清空上下文的应用程序接口（API），因此不做同会话压缩式清空。

需要历史原文时用 `ho_status(view="recall", query="…")` 按 `seq` 回读，命中给前后三行；需要邻近事件时用 `around` 展开。配置建议与验证命令见 [配置参考](docs/reference.md)。

### 交接与续跑

交接按角色分开：全局为 `_Control_Center/records/Global_Handover.md`，项目为 `_Project_Meta/<项目名>/Handover.md`，杂项为 `_Misc/tasks/<任务名>/Handover.md`。

全局任务的交接在 `_Control_Center/tasks/<任务名>/Handover.md`，由全局会话以 `ho_handover` 的 `task` 参数读写。

写交接用 `ho_handover(action="rotate", text=…)` 一步完成：归档旧交接、写入新正文、结构体检，返回承接项。`action="write"` 只用于首次创建，文件已存在时直接报错。归档文件名为 `<原文件名>_<YYYYMMDD_HHMMSS>.md`，同一秒重复时追加 `-2`。交接篇幅以结构控制为主：只写在途与指针。过期内容即删，定期按归档整篇重写；不规定字节数与页数。在此之上约定单份全文不超过 500 行，超限时先删过期内容，不删在途信息。已完成经过、验证记录与需求全文不进交接，分别写台账、计划或归档。

换任由在任会话办理：调用 `ho_handover(action="rotate", text=…)` 重写交接，用户发送 `/allow-reset` 或点击「授权重置」后，会话调用 `ho_sessions(action="succeed")`。插件校验 rotate 留痕、归档哈希、结构体检与授权，建立接任会话并登记在任。任一项不通过则不做任何改动。

### 行动计划

每个任务根有一份 `PLAN.md`，模板为 `_Control_Center/templates/Plan.skeleton.md`，含目标、步骤、验收、风险与状态 5 节。新建计划前，旧计划移入任务根 `_archive/`，之后不再读取；计划随任务归档。

### 体系注册

每个任务一份体系注册：项目写 `_Project_Meta/<项目名>/System.md`，杂项写 `_Misc/tasks/<任务名>/System.md`，全局任务写 `_Control_Center/tasks/<任务名>/System.md`。

全局总注册 `_Control_Center/records/systems.md` 只列各任务体系文件的路径，不承载正文。全局提示段只注入路径清单，项目与杂项提示段注入本任务注册全文。注册写入后立即重装本会话提示段。

`ho_docmap` 的 registry 系列动作提供 read、write 与 check；plan 系列读写 `PLAN.md` 并归档旧计划。read 读本会话注册，write 整份替换并逐条校验路径，check 校验路径与缺失注册。

只有本类别在任会话可以写入；全局不代写项目与杂项的注册。全局的 write 按磁盘任务重建总注册。

### 全局任务库

全局会话可用 `ho_sessions` 的 task-init 动作，在 `_Control_Center/tasks/<任务名>/` 建立任务库。任务库含交接、体系注册、规则与模板副本，并自动登记进全局总注册。

任务库可独立为项目或杂项会话：用 new 动作并传 `from_task`。插件先做整库快照，再一并移入并沿用现有体系，不重建、不重新注册；该动作须用户确认后执行。

### 身份互转与名称注册

项目与杂项可以互转，用 `ho_sessions` 的 role 动作并传 `migrate`。

缺省 auto：先做整库快照，再移动体系与登记。快照落在 `_Archives/_Global/Backups/身份迁移_<YYYYMMDD_HHMMSS>/`。direct：旧体系移入备份目录，新位置按模板新建体系。

项目目标为 `Projects/<项目名>/<项目名>库/`。会话首次用 `ho_sessions(action="office-register")` 注册名称，注册后不得自行修改。名称不超过 40 个字符，不含路径分隔符；已有在任者或同名重复时拒绝注册。改名须由全局处理。

### 暂任与协作

暂任规则在任务库 `rules/Delegation_Rules.md`，协作模板在 `_Control_Center/templates/Prompt_Templates.md`。

交出前刷新交接，提示词写入任务库 `Delegation_Prompt.md`，旧文件移入 `_archive/` 且不再读取；归还时刷新交接并写明暂任者。插件不检查提示词文件是否存在，也不检查是否归档。多会话协作由协调者先 `peer(action="collab", sessions=[…])` 注册，再逐个派任务，用 `peer(action="collect", sessions=[…], timeout_ms=…)` 收结果；谁先完成先返回，同时完成就一起返回。协作期间被交办方不能向交办者或同组成员发明文消息。插件 `peer` 与 DSH 自带 `send_message` 都经守卫拦截。`collect` 取回全部结果后限制自动解除，普通对话不需要注册。`timeout_ms` 按任务预估设置，最低 120 秒。

### 旧体系迁移

`ho_workspace` 的 migrate 动作只在 1.0.0 至 1.1.x 提供，当前版本已移除。
仍停留在 0.9.x 的用户，须先安装 1.0.0 至 1.1.x 完成一次迁移。
1.0.0 及之后的运行数据在首次读取时自动接入，无需手工操作。

### 与官方预设的关系

DSH 的 agent preset（标准、PTC 模式等）决定该会话的系统提示结构与工具表。该预设可在设置里由用户自选或自改。本插件不读取预设名，也不按预设分支，只经官方扩缝注入。工具以 `ctx.tools.register(tool, { when })` 按角色可见性逐步装配；提示以 `systemPrompt.section({ name: 'dsh-handover:manual', order })` 追加自己的命名段落，不改官方提示词正文。换预设不会改变插件的判据、快照、交接与回填流程。唯一相关的是，该预设若没有加载本插件，工具自然不存在。插件不自带预设，也不写用户预设文件，不感知官方工具以原生方式还是 PTC 方式呈现。配置建议与边界见 `docs/reference.md` 的 §8。

## 安装

### 从 GitHub 安装

桌面版：在侧栏「插件」中点击「添加插件」，粘贴仓库地址 `https://github.com/MingMaple/dsh-handover`。Web 界面或命令行：

```bash
dsh plugin --profile web add github:MingMaple/dsh-handover
```

### 从 npm 安装

包名为 `@mingmaple/dsh-handover`，版本与仓库同步；从本地源码安装先执行 `node scripts/build.mjs`，产物在 `dist/`，用插件管理器安装该目录并重启 DSH。

```bash
dsh plugin --profile web add @mingmaple/dsh-handover
```

### 首次使用

1. 打开设置页中的 dsh-handover，在「首次安装」卡片粘贴一个长期目录的绝对路径。
2. 点击「一键部署」。插件在该目录建立 `_Workspace` 与全套结构，注册为全局工作区，并新建全局会话。
3. 在左侧全局工作区打开该会话。只需先铺文件时，点击「仅建立文件体系」，之后再点击「注册为工作区」。
4. 已有工作区但还没有全局会话时，设置页单独出现「全局会话」卡片，可随时补建。

命令行等价操作：`ho_workspace(action="init", parent="<全局根上级目录>", register=true)`，再新建一个标题含「全局」的会话。

## 使用

安装后直接用中文说明要做的事，不必记命令。

| 想做什么 | 可以这样说 |
|---|---|
| 看总体状态 | 先出一份起始简报 |
| 查规则 | 取出 Charter 第 7.2.3 节 |
| 交接并压缩 | 写好交接后压缩并继续 |
| 换任 | 写好交接，由本会话自行换任 |
| 查在任 | 现在全局是谁在任 |
| 设置角色 | 把 Demo1 设为项目角色 |
| 体系与计划 | 把体系注册写进提示段并建立行动计划 |
| 暂任交出 | 把本任务交给另一个会话 |
| 自检 | 检查插件当前状态 |

### 会话角色

| 角色 | 提示段 | 工具数 | 说明 |
|---|---|---|---|
| 全局 | 有 | 6 | 协调会话、维护登记与交接 |
| 项目 | 有 | 5 | 管理单个项目库 |
| 杂项 | 有 | 5 | 管理单个杂项任务 |
| 普通 | 无 | 0 | 不注入提示，不加载工具 |

代理子会话不装配插件工具与 `peer`；子会话在工具表解析阶段即被排除。

### 工具入口

当前为 6 个工具：5 个 `ho_*` 入口与 1 个 `peer`，按 `action` 或 `view` 分流：

- `ho_status`：`view` 取 `phase`、`pressure`、`brief`、`diag`、`drift`、`tokens`、`gate`、`recall`。
- `ho_handover`：`action` 取 `read`、`write`、`rotate`、`archive`、`compact`。
- `ho_docmap`：`action` 取 `registry-*`、`plan-*`、`profile-*`、`changelog-append`、`rules-read`。
- `ho_sessions`：`action` 取 `list`、`role`、`new`、`task-init`、`order`、`place`、`prompt`、`archive`、`unarchive`、`office-read`、`office-register`、`succeed`。
- `ho_workspace`：`action` 取 `init`、`scaffold`、`list`、`create`、`delete`、`move-*`、`backup-*`。
- `peer`：平级会话通信。

项目与杂项看不到 `ho_workspace`；`ho_sessions` 对其仅开放 `succeed`。旧工具名不再注册，调用会得到未知工具提示。

### 设置页

设置页为单页卡片式，常用区展开，低频与长文段折叠。卡片含授权、移动全局根目录、会话角色、全局前置提示词与会话水位。另有通用约束条闸门、交接文档体检与插件信息。末尾有默认折叠的「工具明细」与「使用说明」；删除旧备份须先输入「删除」确认。

## 写作规范

全部产出按 `_Control_Center/standards/写作规范/README.md` 的 W-01 至 W-42 执行；提示段只放一行指针，不注入规范正文。

## 边界与限制

- 压缩依赖 DSH 的 `ctx.compaction` 服务；未挂载时压缩相关工具报错。
- `ptc` 呈现模式下，插件工具只能经程序调用。
- 会话水位依赖宿主保存的会话状态文件布局；字段变化时用 `ho_status(view="diag")` 排查。
- 项目名不超过 24 个字符，任务名不超过 40 个字符。名字不含路径分隔符与控制字符，不以点或空格结尾，不使用设备保留名。
- 插件重载后，已存在的会话沿用旧提示段文本；需要新文本时重启 DSH 或新建会话。
- 服务端是纯 Node ESM，不调用 PowerShell、cmd 或 bash；Windows、macOS 与 Linux 同一套代码。路径大小写按平台处理，7-Zip 缺失时用内置 tar.gz。
- 卸载后残留仅 `~/.dsh/storages/dsh-handover.*`（角色表、授权与运行日志）与日志目录；会话级产物在会话目录内，随会话删除。删除这些残留即可清零。
- 插件本体不含用户项目、会话或账号数据；用户数据与角色表保存在本机。

## 开发

源码在 `src/`；`dist/` 为构建产物，不入版本库。构建与校验命令见 `package.json` 的 `scripts`。服务端代码替换 `dist/` 后，在插件列表停用再启用即生效。客户端构建产物不热更新，改设置页须重建并重启 DSH。
