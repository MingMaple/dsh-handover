# dsh-handover

DeepSeek Harness（DSH）插件：跨会话完成长任务的工作流。上下文到线自动压缩并写好交接，必要时换任。任务较重时先写计划。任务或整个项目可交给 DSH 之外的会话。插件只使用宿主公开的扩展点，不改动 DSH 本体。

当前版本 1.0.5。支持 DSH 0.2.1-rc.2 至 0.3.0，不含 0.3.0 及其候选版；准确范围见 `package.json` 的 `engines.dsh`。已在 0.2.2-rc.5 上实测通过。

## 为什么需要

单个会话的上下文越用越多，用到一定程度之后，出错的可能也会随之上升；可若这时压缩上下文，或者写好交接换一个会话，又会丢掉已经积累的信息。面对这样的两难，有没有更好的取舍？

本插件一定能很好地帮助你。来试试吧；不满意，随时关闭插件并删除即可。

## 核心机制

### 任务流程

层级一为轻量任务：单文件修改、局部改名、语法修复、格式化与内容读取。此类任务直接执行，不写计划，不做查证。

用户说「讨论一下」，或助手已就流程询问过用户时，执行前须再确认。用户明确说「直接做」的除外。

层级二为繁重任务：新增功能、多文件联动、重构、架构或接口变更。按以下顺序执行。

1. 先估算纯窗口是否会超过 40%，当前占用不计入。
2. 在任务根写 `PLAN.md`。超过 40% 时，计划里安排拆子智能体，助手只做统筹与收尾；没超过就按自行完成来写。写完回看上下文核对。
3. 子智能体按成本使用。单个子智能体自身亦需十余步，结论还要回读。只有同时满足以下条件才派：单块 ≥15 步或需读 ≥10 个文件；确需隔离；结果能机械验收。并发 ≤3。能写成脚本再抽检的，先写脚本。子智能体的数量与各自的步数写入计划，随计划确认。同一批文件的下一道工序交回原作者续用（`send_message`），不另开。细则见 Charter §十一 与运行时手册 §12.4。
4. 发现缺口时给出方案询问用户；优劣不明时并列全部方案。
5. 用户确认后执行。

子智能体提示词由助手放入规范文件地址与体系说明；插件不向其上下文注入内容。

余量不足时先压缩或办理换任。压缩后按胶囊继续；换任后按「先读交接、再读计划、后执行」恢复。

### 上下文与压缩

上下文按 token 分档：整理线 soft、建议线 advise、强制线 hard。3 档均为当前窗口比例：35%、50%、65%，不扣预留输出、不设绝对 token。200K 窗即 70K/100K/130K，1M 窗即 350K/500K/650K。窗口读不到时不判定，不注入档位提示。

每轮开始时追加一行压力画像：水位、余量、近 3 轮增速与 3 档线。整理线与建议线只注入提示：请将当前任务做到合适断点处后进行上下文压缩流程。到建议线后按胶囊标准写。助手胶囊按 6 项写：目标、已定方案、下一步、易错点、必须遵守的约束原文、需要保留的原文位置。写好后调用 `ho_handover(action="compact", capsule=…)`。强制线由插件机制兜底：插件将立即执行压缩，不要求助手先到断点。提示在同一会话同一档位只注入一次，压缩成功后重置。宿主压缩引擎保持默认阈值 0.8，只作兜底观测，插件不改宿主阈值。

压缩前写会话锚点：`<会话目录>/dsh-handover/anchor.md`。锚点含目标、约束原文、已确认事实与指针、未完成与下一步。压缩后注入胶囊。助手主动压缩取全量范围，压到当前步之前。强制线保留尾部：最近 20 条与 8000 token。助手自述胶囊保留正文原样。抬头只加压缩前后 token、缩减比、次序与召回提示。正文上限 4000 字，超过即拒绝，不截断。渲染后 4600 字为参考上限，只报告。机制兜底胶囊只放锚点与最近 6 轮关键词摘录。锚点含目标、约束逐条原文与状态。关键词为下一步、待办、未完成、待确认、待修、错误、失败、异常、路径。抽不到写「（无）」。助手胶囊与 DSH 摘要互补，不读旧交接全文。交接只在更替会话时使用。

微观层的微快照只在压缩前写入：助手入口与强制线各一次。6 项为目标、已确认事实、未决、下一步、指针、时刻；条目须可核对，引路径不抄原文，缺项写「未核，待确认」。快照与提示状态存放在会话目录内 `dsh-handover/`，会话目录被删除时随之消失。

宏观重置的 4 条保留为追加提示理由。前三条为：累计遮蔽不少于 2 倍窗口；压缩增量比低于 0.5；同错或同文件重复不少于 2 次。第四条为里程碑或用户要求。

每次压缩成功计数加一，助手触发与强制压缩都计。助手入口与到线提示在 4 次后关闭，强制线兜底至 6 次，此后只办理更替会话。换任由 `ho_handover(action="rotate", text=…)` 一步完成归档、写入与体检；承接项由工具返回，需自行并入新正文。用户授权后调用 `ho_sessions(action="succeed")`。宿主没有清空上下文的应用程序接口（API），因此不做同会话压缩式清空。

需要历史原文时用 `ho_status(view="recall", query="…")` 按 `seq` 回读，命中给前后三行；需要邻近事件时用 `around` 展开。配置建议与验证命令见 [配置参考](docs/reference.md)。

### 交接与换任

交接按角色分开：全局为 `_Control_Center/records/Global_Handover.md`，项目为 `_Project_Meta/<项目名>/Handover.md`，杂项为 `_Misc/tasks/<任务名>/Handover.md`。

全局任务的交接在 `_Control_Center/tasks/<任务名>/Handover.md`，由全局会话以 `ho_handover` 的 `task` 参数读写。

写交接用 `ho_handover(action="rotate", text=…)` 一步完成：归档旧交接、写入新正文、结构体检，返回承接项。`action="write"` 只用于首次创建，文件已存在时直接报错。归档文件名为 `<原文件名>_<YYYYMMDD_HHMMSS>.md`，同一秒重复时追加 `-2`。交接篇幅以结构控制为主：只写在途与指针。过期内容即删，定期按归档整篇重写；不规定字节数与页数。在此之上约定单份全文不超过 500 行，超限时先删过期内容，不删在途信息。已完成经过、验证记录与需求全文不进交接，分别写台账、计划或归档。

换任由在任会话办理：调用 `ho_handover(action="rotate", text=…)` 重写交接，用户发送 `/allow-reset` 或点击「授权重置」后，会话调用 `ho_sessions(action="succeed")`。插件硬闸共 9 项，原交接不存在、无需归档时按 8 条计。通过后校验授权，建立接任会话并登记在任。任一项不通过则不做任何改动。

### 分叉与会话角色

会话被分叉后，宿主只复制历史，不复制角色条目。识别依据是会话头 `isSeeded` 为真，且日志里有早于创建时间的继承事件。

识别后按会话工作目录补一条 `source="fork"` 的角色条目。落在 `Projects/<项目>/` 的认定为该项目，落在 `_Misc/tasks/<任务>/` 的认定为该杂项任务。工作目录在全局根或推不出身份时不猜，等用户设定。

注册是家族属性，可以沿用；在任是唯一属性，不随分叉复制。分叉副本照常看到 `ho_*`、读同一份交接，但交接只读：本会话不是该世系在任者时，`write`、`rotate`、`archive` 一律拒绝并给出处置。要承继在任，由用户先在设置页把在任改记到某个分叉，之后它才能落笔。抽卡时多个候选共享同一角色注册，互不抢占在任。

### 行动计划

每个任务根有一份 `PLAN.md`，模板为 `_Control_Center/templates/Plan.skeleton.md`，含目标、步骤、验收、风险与状态 5 节。新建计划前，旧计划移入任务根 `_archive/`，之后不再读取；计划随任务归档。

### 体系注册

每个任务一份体系注册：项目写 `_Project_Meta/<项目名>/System.md`，杂项写 `_Misc/tasks/<任务名>/System.md`，全局任务写 `_Control_Center/tasks/<任务名>/System.md`。

全局总注册 `_Control_Center/records/systems.md` 只列各任务体系文件的路径，不承载正文。全局提示段只注入路径清单，项目与杂项提示段注入本任务注册全文。注册写入后立即重装本会话提示段。

`ho_docmap` 的 registry 系列动作提供 read、write 与 check；plan 系列读写 `PLAN.md` 并归档旧计划。read 读本会话注册，write 整份替换并逐条校验路径，check 校验路径与缺失注册。

只有本类别在任会话可以写入；全局不代写项目与杂项的注册。全局的 write 按磁盘任务重建总注册。

### 全局任务库

全局会话可用 `ho_sessions` 的 task-init 动作，在 `_Control_Center/tasks/<任务名>/` 建立任务库。任务库含交接、体系注册、规则与模板副本，并自动登记进全局总注册。

任务库可独立为项目或杂项会话：用 new 动作并传 `from_task`。插件先做整库快照，再一并移入并沿用现有体系，不重建、不重新注册；该动作须用户确认后执行。

### 身份与布局

会话身份分两轴：角色（类别）决定权限与登记，布局决定文件落点。角色为全局、项目、杂项、普通；布局为项目布局、杂项布局、全局任务布局，缺省与角色同类同名。

项目与杂项互转用 `ho_sessions` 的 role 动作。缺省先问后迁：写入新身份后文件零移动，该会话首轮询问是否迁移。选不迁移则沿用原布局；选迁移则整库快照后按新布局搬移，并改写与登记身份字段。显式 `migrate="auto"` 直接整库快照后移动；`migrate="direct"` 把旧体系移入备份目录，新位置按模板新建。改名与改身份走同一套流程。

落点：项目为库根 `Projects/<项目名>/<项目名>库/` 与元数据 `_Project_Meta/<项目名>/`，杂项为 `_Misc/tasks/<任务名>/`，全局任务为 `_Control_Center/tasks/<任务名>/`。快照落在 `_Archives/_Global/Backups/身份迁移_<YYYYMMDD_HHMMSS>/`。

会话首次用 `ho_sessions(action="office-register")` 注册名称，注册名一经写入即固定，改名由全局处理。名称不超过 40 个字符，不含路径分隔符；已有在任者或同名重复时拒绝注册。

### 暂任与协作

暂任是把一段工序或整个项目交给外部会话执行，在任会话不变。外部会话不在 DeepSeek Harness（DSH）内，没有插件工具与 `peer`，只有宿主文件工具与宿主子智能体。暂任不是换任：不申请换任授权，不建接任会话，交出方仍是在任者。规则见任务库 `rules/Delegation_Rules.md` 与 `rules/External_Takeover_Rules.md`，归还三法与对话示例见 [使用说明](docs/usage.md)，协作模板在 `_Control_Center/templates/Prompt_Templates.md`。

交出前刷新交接，提示词写入任务库 `Delegation_Prompt.md`，旧文件移入 `_archive/` 且不再读取；归还时刷新交接并写明暂任者。插件不检查提示词文件是否存在，也不检查是否归档。多会话协作只用于 DSH 插件会话。协调者先 `peer(action="collab", sessions=[…])` 注册，再逐个派任务。用 `peer(action="collect", sessions=[…], timeout_ms=…)` 收结果：谁先完成先返回，同时完成就一起返回。协作期间被交办方不能向交办者或同组成员发明文消息。插件 `peer` 与 DSH 自带 `send_message` 都经守卫拦截。`collect` 取回全部结果后限制自动解除，普通对话不需要注册。`timeout_ms` 按任务预估设置，最低 120 秒。

### 旧体系迁移

`ho_workspace` 的 migrate 动作只在 1.0.0 至 1.1.x 提供，当前版本已移除。
仍停留在 0.9.x 的用户，须先安装 1.0.0 至 1.1.x 完成一次迁移。
1.0.0 及之后的运行数据在首次读取时自动接入，无需手工操作。

### 与官方预设的关系

DSH 的 agent preset（标准、PTC 模式等）决定该会话的系统提示结构与工具表。该预设可在设置里由用户自选或自改。本插件不读取预设名，也不按预设分支，只经官方扩缝注入。工具以 `ctx.tools.register(tool, { when })` 按角色可见性逐步装配；提示以 `systemPrompt.section({ name: 'dsh-handover:manual', order })` 追加命名段落，不改官方提示词正文。换预设不改变本插件的判据、快照与交接流程。与本插件相关的只有一点：预设未加载本插件时，工具不存在。本插件不自带预设，也不写用户预设文件；不感知官方工具以原生方式还是 PTC 方式呈现。配置建议与边界见 `docs/reference.md` 的 §8。

## 安装

### 从 GitHub 安装

桌面版：在侧栏「插件」中点击「添加插件」，粘贴仓库地址 `https://github.com/MingMaple/dsh-handover`。Web 界面或命令行：

```bash
dsh plugin --profile web add github:MingMaple/dsh-handover
```

### 从 npm 安装

包名为 `@mingmaple/dsh-handover`，版本与仓库同步；从本地源码安装先执行 `node scripts/build.mjs`，产物在 `dist/`，用插件管理器安装该目录并重启 DSH。

```bash
dsh plugin --profile web add @mingmaple/dsh-handover
```

### 首次使用

首次安装、建项目或杂项、建文件体系、换任与暂任等全部流程见 [使用说明](docs/usage.md)。

命令行等价操作：`ho_workspace(action="init", parent="<全局根上级目录>", register=true)`，再新建一个标题含「全局」的会话。

## 参考

### 会话角色

| 角色 | 提示段 | 工具数 | 说明 |
|---|---|---|---|
| 全局 | 有 | 6 | 协调会话、维护登记与交接 |
| 项目 | 有 | 5 | 管理单个项目库 |
| 杂项 | 有 | 5 | 管理单个杂项任务 |
| 普通 | 无 | 0 | 不注入提示，不加载工具 |

代理子会话不装配插件工具与 `peer`；子会话在工具表解析阶段即被排除。

### 工具入口

当前为 6 个工具：5 个 `ho_*` 入口与 1 个 `peer`，按 `action` 或 `view` 分流：

- `ho_status`：`view` 取 `phase`、`pressure`、`brief`、`diag`、`drift`、`tokens`、`gate`、`recall`。
- `ho_handover`：`action` 取 `read`、`write`、`rotate`、`archive`、`compact`。
- `ho_docmap`：`action` 取 `registry-*`、`plan-*`、`profile-*`、`changelog-append`、`rules-read`。
- `ho_sessions`：`action` 取 `list`、`role`、`new`、`task-init`、`order`、`place`、`prompt`、`archive`、`unarchive`、`office-read`、`office-register`、`succeed`、`migration-choice`。
- `ho_workspace`：`action` 取 `init`、`scaffold`、`list`、`create`、`delete`、`move-*`、`backup-*`。
- `peer`：平级会话通信；投递前先唤醒目标会话，已归档的会话会被拦下，须先解除归档。

项目与杂项看不到 `ho_workspace`；`ho_sessions` 对其仅开放 `succeed`。旧工具名不再注册，调用会得到未知工具提示。

### 设置页

设置页为单页卡片式，常用区展开，低频与长文段折叠。卡片含授权、移动全局根目录、会话角色、全局前置提示词与会话水位。另有通用约束条闸门、交接文档体检与插件信息。末尾有默认折叠的「工具明细」与「使用说明」；删除旧备份须先输入「删除」确认。

页头有「对齐检查」：唤醒全局在任会话，让它读插件内置的对齐标准文件。全局用 `ho_status(view="align")` 一条命令核对各项目与杂项的文件体系。报告分 7 组：配置改动、副本缺节、骨架未注册、注册缺文件。还有约束条未过、交接未跟上与在任登记缺条目。它出完清单先问补哪些，得到选择后才动手。没有全局在任时只报错，不替用户建会话。版本说明标「建议状态刷新」的版本，升级后点击一次。标「无需」的纯维护版本不点也不影响。

## 边界与限制

- 压缩依赖 DSH 的 `ctx.compaction` 服务；未挂载时压缩相关工具报错。
- `ptc` 呈现模式下，插件工具只能经程序调用。
- 会话水位依赖宿主保存的会话状态文件布局；字段变化时用 `ho_status(view="diag")` 排查。
- 项目名不超过 24 个字符，任务名不超过 40 个字符。名字不含路径分隔符与控制字符，不以点或空格结尾，不使用设备保留名。
- 插件重载后，已存在的会话沿用旧提示段文本；需要新文本时重启 DSH 或新建会话。
- 服务端是纯 Node ESM，不调用 PowerShell、cmd 或 bash；Windows、macOS 与 Linux 同一套代码。路径大小写按平台处理，7-Zip 缺失时用内置 tar.gz。
- 卸载后残留仅 `~/.dsh/storages/dsh-handover.*`（角色表、授权与运行日志）与日志目录；会话级产物在会话目录内，随会话删除。删除这些残留即可清零。
- 插件本体不含用户项目、会话或账号数据；用户数据与角色表保存在本机。

## 开发

源码在 `src/`；`dist/` 为构建产物，不入版本库。构建与校验命令见 `package.json` 的 `scripts`。服务端代码替换 `dist/` 后，在插件列表停用再启用即生效。客户端构建产物不热更新，改设置页须重建并重启 DSH。
