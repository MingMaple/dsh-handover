# 常见故障处理

## 工具缺失或数量不对

1. 在全局会话执行 `ho_diag`，看「角色判定与工具集」一节。
2. 全局应为 22 个，项目与杂项 9 个，普通 0 个。
3. 新建会话时角色表中尚无该会话，插件会判为普通，并在 1.5 秒与 4.5 秒后复核。角色写入后应自动装配。
4. 仍未装配时，在设置页「会话角色」卡片里重新设一次角色；仍无效则执行 `ho_diag` 查 `roleGating` 字段。
5. 改过源码但未生效：执行 `node scripts/build.mjs`，然后在插件列表停用并启用一次，不必重启 DSH。提示段文本不随重载替换，仍显示旧文本时重启 DSH。
6. 子会话不装配 `ho_` 与 `peer_` 工具，属正常：子会话在工具表解析阶段即被排除，与角色设置无关。

## 工作区未接入

`ho_diag` 或设置页显示未接入时，走设置页「首次安装」卡片，或执行：

```text
ho_init(parent="<已存在目录的绝对路径>", register=true)
```

装配里没有写死 `workspaceRoot`。工具侧按配置项、会话工作目录向上查找的顺序定位，向上找不到时再查工作区登记；设置页没有会话上下文，按配置项、标题含「全局」且带 `_Control_Center` 的工作区、任一带 `_Control_Center` 的工作区定位。

## 设置页刷新失败

页面保留上次读数，并显示其时间与失败原因。常见原因：

- 宿主没有 `connection` 服务：插件改用 HTTP 回退；纯 CLI 场合回退会被静默跳过。
- 桌面版 GUI 对非浏览器策略请求返回 403：不要用裸 `fetch` 取数，插件已走 `/api` 载体。
- 请求超时：页面加载 30 秒、状态 8 至 30 秒、写操作 15 至 900 秒；稍后重试。

## 压缩未生效

1. 压缩须由用户在设置页点「压缩授权」，单次授权 5 分钟内有效，或在聊天框发送 `/allow-compact`。
2. `ho_checkpoint` 只登记，由调度器在回合结束后执行；目标必须空闲。
3. 交接体检不通过时拒绝排压缩，先用 `ho_handover(action=read)` 检查结构。
4. 已压满 3 次后不再压缩，应换任：`ho_sessions(action="new")`，须用户同意后传 `confirm=true`。额度用尽的判定先于水位；低水位与 `force` 均不能越过，`ho_sessions` 的压缩指令（`action="order", order="compact"`）同样会被拒绝。

## 项目名或任务名不合法

工具报出「项目名不合法」「任务名不合法」一类错误时，说明名字不能作为目录名使用；此时不写入磁盘，也不改动登记。按下列规则改名后重试：

- 项目名不超过 24 字符，任务名不超过 40 字符。
- 不含 `< > : " / \ | ? *` 与控制字符，不以点或空格结尾，不使用 `CON`、`NUL`、`COM1` 这类设备保留名。
- 名字通常从会话工作目录、首条提示或标题推断。若报错指出名字含 `*` 等字符，检查首条提示中是否将 `Projects/**` 这类通配写法写在与项目名相邻的位置。

名字合法但被判为普通角色的会话，用设置页「会话角色」卡片或 `ho_sessions(action="role")` 明确设定。

## 迁移后原路径失效

若链接被误删，页面会显示「原路径不存在」与「重建链接」。执行：

```text
ho_workspace(action="move-repair")
```

只重建链接，不改动文件。若新位置也不存在，先确认数据实际位置，再决定是否回退。

## 交接体检报「缺节」

项目交接至少要有「正在做的事」与「下一步」两节；全局交接需要 §0 至 §7 全套，§0 含七个字段，§7 至少一行 session id。缺节允许压缩，不合格必须先补齐。
