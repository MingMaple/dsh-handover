# 常见故障处理

## 工具缺失或数量不对

1. 在全局会话执行 `ho_diag`，看「角色判定与工具集」一节。
2. 全局应为 22 个，项目与杂项 9 个，普通 0 个。
3. 新建会话出生时角色表里还没有它，插件会判为普通，并在 1.5 秒与 4.5 秒后复核。角色写入后应自动装配。
4. 仍未装配时，在设置页「会话角色」卡片里重新设一次角色；仍无效则执行 `ho_diag` 查 `roleGating` 字段。
5. 改过源码但没生效：执行 `node scripts/build.mjs` 并重启 DSH。`dist/` 是安装面。

## 工作区未接入

`ho_diag` 或设置页显示未接入时，走设置页「首次安装」卡片，或执行：

```text
ho_init(parent="<已存在目录的绝对路径>", register=true)
```

装配里没有写死 `workspaceRoot`，插件按以下顺序定位：配置项、标题含「全局」且带 `_Control_Center` 的工作区、任一带 `_Control_Center` 的工作区、会话工作目录向上查找。

## 设置页刷新失败

页面保留上次读数，并显示其时间与失败原因。常见原因：

- 宿主没有 `connection` 服务：插件改用 HTTP 回退；纯 CLI 场合回退会被静默跳过。
- 桌面版 GUI 对非浏览器策略请求返回 403：不要用裸 `fetch` 取数，插件已走 `/api` 载体。
- 请求超时：页面加载 30 秒、状态 8 至 30 秒、写操作 15 至 900 秒；稍后重试。

## 压缩未生效

1. 压缩须由用户在设置页点「压缩授权」，单次授权 5 分钟内有效，或在聊天框发送 `/allow-compact`。
2. `ho_checkpoint` 只登记，由调度器在回合结束后执行；目标必须空闲。
3. 交接体检不通过时拒绝排压缩，先用 `ho_handover(action=read)` 检查结构。
4. 已压满 3 次后不再压缩，应换任：`ho_sessions(action="new")`，须用户同意后传 `confirm=true`。

## 迁移后原路径失效

若链接被误删，页面会显示「原路径不存在」与「重建链接」。执行：

```text
ho_workspace(action="move-repair")
```

只重建链接，不改动文件。若新位置也不存在，先确认数据实际位置，再决定是否回退。

## 交接体检报「缺节」

项目交接至少要有「正在做的事」与「下一步」两节；全局交接需要 §0 至 §7 全套，§0 含七个字段，§7 至少一行 session id。缺节允许压缩，不合格必须先补齐。
