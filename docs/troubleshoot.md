# 常见故障处理

## 工具缺失或数量不对

1. 在全局会话执行 `ho_status(view="diag")`，看「角色」与「角色装配」两行。
2. 全局应为 14 个，项目 11 个，杂项 10 个，普通 0 个。
3. 新建会话时角色表中尚无该会话，插件会判为普通；角色写入后，该会话下一轮请求即按新角色装配。
4. 仍未装配时，在设置页「会话角色」卡片里重新设一次角色；仍无效则执行 `ho_status(view="diag")` 查 `roleGating` 字段。
5. 改过源码但未生效：执行 `node scripts/build.mjs`，然后在插件列表停用并启用一次，不必重启 DSH。提示段文本不随重载替换，仍显示旧文本时重启 DSH。
6. 子会话不装配 `ho_` 与 `peer` 工具，属正常：子会话在工具表解析阶段即被排除，与角色设置无关。

## 工作区未接入

`ho_status(view="diag")` 或设置页显示未接入时，走设置页「首次安装」卡片：粘贴绝对路径后点「一键部署」，文件体系、工作区与会话一次建好；也可以只点「仅建立文件体系」，再点「注册为工作区」。命令行等价操作：

```text
ho_workspace(action="init", parent="<已存在目录的绝对路径>", register=true)
```

装配里没有写死 `workspaceRoot`。工具侧按配置项、会话工作目录向上查找的顺序定位，向上找不到时再查工作区登记；设置页没有会话上下文，按配置项、标题含「全局」且带 `_Control_Center` 的工作区、任一带 `_Control_Center` 的工作区定位。

## 新建会话报「必须指明工作区」

`ho_sessions(action="new")` 必须落到明确的工作区：传 `workspace`（id、标题或路径），或传某个已注册工作区根的 `cwd`。两者都没有，或项目没有对应工作区时，工具会报错并列出已注册的工作区，不会静默落到调用者所在的工作区。

处置：

1. 先看清单：`ho_workspace(action="list")`，或直接读报错文本里的清单。
2. 还没有工作区时先建：`ho_workspace(action="create", path="<目录>", title="<标题>", ensure=true)`。`ensure=true` 会在目录不存在时自动创建。
3. 再建会话：`ho_sessions(action="new", confirm=true, workspace="<id 或标题>", title="<标题>")`。项目会话可同时传 `project`，插件会按同名工作区匹配。

## 设置角色后工具没有变化

会话休眠时设定角色，插件会在它下次开轮时装配工具与提示段，不必重启 DSH。若仍看不到应有的工具：

1. 在设置页「会话角色」重新设定一次，注意「存活会话当场生效」一栏的提示。
2. 执行 `ho_status(view="diag")`，看「角色装配」一行里的已装配会话数与最近时间。
3. 插件刚从旧版本换上来时，已存在的会话沿用旧提示段文本；重启 DSH 一次即换成新文本，工具裁剪不受影响。

## 设置页刷新失败

页面保留上次读数，并显示其时间与失败原因。常见原因：

- 宿主没有 `connection` 服务：插件改用 HTTP 回退；纯 CLI 场合回退会被静默跳过。
- 桌面版 GUI 对非浏览器策略请求返回 403：不要用裸 `fetch` 取数，插件已走 `/api` 载体。
- 请求超时：页面加载 30 秒、状态 8 至 30 秒、写操作 15 至 900 秒；稍后重试。

## 压缩未生效

1. 压缩须由用户在设置页点「压缩授权」，单次授权 5 分钟内有效，或在聊天框发送 `/allow-compact`。
2. `ho_checkpoint` 只登记，由调度器在回合结束后执行；目标必须空闲。
3. 交接体检不通过时拒绝排压缩，先用 `ho_handover(action=read)` 检查结构。
4. 已压满 3 次后不再压缩，应换任：由本会话写好交接后调用 `ho_succeed` 自行换任，须用户先发送 `/allow-succeed` 授权。额度用尽的判定先于水位；低水位与 `force` 均不能越过，`ho_sessions` 的压缩指令（`action="order", order="compact"`）同样会被拒绝。

## 换任未执行

`ho_succeed` 报「换任未执行，未做任何写入」时，按报出的原因逐项处理：

1. 没有授权：由用户在聊天框发送 `/allow-succeed`（可留空，也可带 8 位短号授权别的会话），或在设置页「压缩授权」卡片的「换任授权」区域点「允许换任」。授权一次性、5 分钟有效、按会话生效；压缩授权不能顶替换任授权。
2. 不是在任者：只有登记表中该类会话的现任本人可以换任；已记过一次换任的旧会话也不得再次换任。先用 `ho_office` 确认现任的名字与会话 id，再由现任会话执行。
3. 交接体检不合格：报错逐条列出缺项——「下一步」一节缺失或没有条目、内容为空、仍有「待填」「TODO」一类占位符。补齐后用 `ho_handover(action=read)` 复核，再重新调用。

## 项目名或任务名不合法

工具报出「项目名不合法」「任务名不合法」一类错误时，说明名字不能作为目录名使用；此时不写入磁盘，也不改动登记。按下列规则改名后重试：

- 项目名不超过 24 字符，任务名不超过 40 字符。
- 不含 `< > : " / \ | ? *` 与控制字符，不以点或空格结尾，不使用 `CON`、`NUL`、`COM1` 这类设备保留名。
- 名字通常从会话工作目录、首条提示或标题推断。若报错指出名字含 `*` 等字符，检查首条提示中是否将 `Projects/**` 这类通配写法写在与项目名相邻的位置。

名字合法但被判为普通角色的会话，用设置页「会话角色」卡片或 `ho_sessions(action="role")` 明确设定。

## 文档定位报路径失效

`ho_gate` 的「文档定位 map」一节报「失效 N 条」时，说明 map 里列的某个路径已被移动或删除。由该血脉的在任会话执行：

```text
ho_docmap(action="check")
ho_docmap(action="write", entries=[{ path: "<新路径>", about: "<一句话介绍>", when: "<何时读>" }])
```

map 整份替换，写入前逐条校验路径存在，缺项整条拒绝。只有该血脉在任者能写，已交出的旧会话只读；全局不代写项目与杂项的 map。

## 按规范做事时找不到规范

用户提到某个规范而手头没有时，按两处查找：当前库内有无同名规范，以及 `_Control_Center/standards/` 下有无同名子目录。

1. 先看本库：规范可能就在本库的文档目录内，本库那份优先。
2. 再看规范库：直接列 `_Control_Center/standards/` 下的子目录，目录名即规范名；该目录只有 `README.md` 说明时表示尚无共用规范。
3. 两处都没有：不要凭记忆补全步骤，向用户说明缺哪份规范，由其决定新建还是改用别的口径。
4. 需要新增或改写时：未指明范围就写本库（会话所在的工作区）；说「写入通用规范库」「写成通用规范」「写成共用规范」的才由全局会话在 `_Control_Center/standards/<规范名>/` 下写 `README.md`，项目与杂项会话只读、报全局。

## 授权后会话没有反应

授权写入后，目标会话的提示段会在下一轮开头带上「用户已授权…至…（一次性，用后失效）」。正在作业的会话要等它下一个请求；空闲会话不会因此被唤醒。可用 `ho_status(view="phase")` 查看授权状态与剩余分钟。授权过期未用属于正常，重新授权即可。

## 迁移后原路径失效

若链接被误删，页面会显示「原路径不存在」与「重建链接」。执行：

```text
ho_workspace(action="move-repair")
```

只重建链接，不改动文件。若新位置也不存在，先确认数据实际位置，再决定是否回退。

## 交接体检报「缺节」

项目交接至少要有「正在做的事」与「下一步」两节；全局交接需要 §0 至 §7 全套，§0 含七个字段，§7 至少一行 session id。缺节允许压缩，不合格必须先补齐。
