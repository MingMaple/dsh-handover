# 0.9.16

新增通用规范库：跨会话共用的做法集中放在 `_Control_Center/standards/`，一条规范一个子目录，可随附脚本；三档角色的常驻段各增加一行，说明该目录属于规范的查找范围。已部署的工作区可用 `ho_workspace(action="scaffold")` 一次补齐。

## 通用规范库

- 位置与结构：`_Control_Center/standards/`，目录名即规范名；正文入口为子目录内的 `README.md`，规范自带的脚本与附件放在同一子目录，不混入 `_Control_Center/tools/`。
- 权限：任何角色的会话都可读；新增与改写只由全局会话执行，项目与杂项会话只读。
- 首次部署时建立该目录并写入一份 `README.md`，说明结构、查找、写入三条口径；目录内仅有这份说明时表示尚无共用规范。
- 查找顺序：先看本库有无同名规范，再看规范库；两处都有时按本库那份执行，规范库那份作为通用版本。该口径写在规范库的 `README.md` 内。
- 规范正文只写做法、判据与验收条件，不记某一次作业的进度与结果；进度归交接与台账。

## 提示段

全局、项目、杂项三档的常驻段各增加一行：

> 通用规范在 `_Control_Center/standards/`（每条一个子目录）；当前用户提到「按某某规范进行」时，本库与该目录都算查找范围。

该行与流程手册的指针并列放在「按需取用」位置。普通会话不注册提示段，不受影响。

## 既有工作区的补齐

`ho_workspace` 新增 `action="scaffold"`：在已部署的全局根上补齐缺失的目录与说明文件。只新建，不覆盖，已有文件的内容一字未改；二次执行无改动。

`action="init"` 仍只对空的或不存在的位置生效，因此已部署的工作区不会自动获得新目录，需要时执行一次 `scaffold`。设置页的「一键部署」对新位置一次铺全，无需再用该动作。

## 文案术语

用户可见文案统一为一套称谓：指导会话行为的文本（提示段、工具描述、工具输出与错误消息）里，发起请求的人写「当前用户」，指代读者时用第二人称；给人读的文档里，受益的最终用户写「用户」，安装与维护的人写「插件使用者」；指一次交互上下文一律写「会话」，不再用「对话」代替。改动覆盖三档角色段、工具描述与输出、设置页说明与斜杠命令描述；面向人的文档与代码标识符按同一口径分别处理。
