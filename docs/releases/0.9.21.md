# 0.9.21

设置页「使用说明」逐条核对并修正：起始简报范围、授权入口、压缩去向、打包格式、会话清点输出、自检项与文档定位权限均按当前实现改写；示例句与说明统一为规范书面语。另修一处交接体检的误判。工具与提示段不变。

## 自 v0.9.14 以来的累计变化

0.9.15 至 0.9.20 均未单独发布，本次一并发布，累计变化如下。

- 工具整合：入口由 24 个降为 14 个（13 个 `ho_*` 与 `peer`），按「一次做一件事」合并；旧工具名不设兼容桩，替代关系见各版本说明与 README「工具整合」。
- 文档定位：`ho_docmap` 提供读、写、查；按血脉权限写入，只允许该血脉在任者写；写入前逐条校验路径、覆盖前留 `.bak`、写盘后当场重装提示段；`ho_gate` 增加路径检查。
- 授权提示：用户授权压缩或换任后，目标会话的提示段在下一轮多一行到期时刻与一次性说明；`ho_status` 的 `phase` 与 `brief` 视图给出「授权」一行。
- 交接类文档不设体积上限：只判结构与占位符。
- 通用规范库：`_Control_Center/standards/` 一条规范一个子目录；三档角色段加查找指针；写入分两档（默认写本库，明确「写入通用规范库」一类说法才写共用库）；`ho_workspace(action="scaffold")` 用于补齐既有工作区。
- 设置页：授权卡改名并按在任会话折叠；「待处理」合并进既有卡片；工具清单独立为默认折叠的「工具明细」；会话水位、通知与交接体检统一以 `_Control_Center/records/Office.json` 的在任为准，普通会话不参与；交接体检只查已登记的项目与杂项；会话角色按全局、项目、杂项、普通排列；迁移卡片不再把保留的旧备份当作待处理；全页文案与注释改为规范书面语。

## 交接体检

- 「下一步待办」（含全局 §2）的条目判定此前只认 `-`、`*` 两种无序列表；用 `1.` 撰写的交接会被误判为「没列出任何条目」。现同时接受 `-`、`*`、`+` 与 `1.`、`1)`、`1、` 开头的行。

## 核对修正

| 条目 | 原说法 | 现状与改法 |
|---|---|---|
| 起始简报 | 水位、闸门、会话清点与阶段建议 | 简报还含交接漂移，补上 |
| 换任 | 只写聊天框 `/allow-succeed` | 补设置页「授权」卡点击「授权换任」这条入口 |
| 压缩去向 | 「由助手选择压缩后去向」 | 明确为登记时以 `resume` 选定：未完成用 `continue` 续跑，已收尾用 `wait`（压缩后不唤醒） |
| 打包迁移 | 「7z」 | 按实际：有 7-Zip 用 7z，否则内置 tar.gz |
| 查看会话 | 「在任或前任」 | 该输出为水位、运行状态、活跃或沉默、角色、最后活动，并给出本轮通知名单 |
| 自检 | 服务、调度器、压缩计数、角色与工具集 | 另含水位与迁移状态 |
| 文档定位 | 只写路径与注入 | 补「空 map 不注入，只有该血脉在任者能写」 |
| 项目骨架 | 「由该项目会话自己写文件并注册」 | 改为「档案文件由该项目会话自己写」；注册动作由 `ho_profile` 完成 |
| 归档会话 | 「删除会话」 | 标题改为「归档会话」；DSH 只提供归档，再次唤醒须先解归档 |
| 引入段 | 「全部功能都在会话中调用」 | 改为「主要在会话中调用」，并列出设置页的授权、迁移、会话角色入口 |

## 措辞

- 「可以这样说」一列改为可直接提出的要求，不再用口语化说法（例如「查询本会话的上下文水位」「取出 Charter 第 7.2.3 节」）。
- 「插件会执行的动作」一列统一用陈述句，动词与工具输出对齐；工具明细中 `ho_checkpoint` 的说明改为「回合结束后压缩，并按 resume 决定是否续跑」。

## 升级

替换 `dist/` 后在插件列表停用再启用；浏览器半不热更新，需刷新设置页。本版未改提示段与工具。
