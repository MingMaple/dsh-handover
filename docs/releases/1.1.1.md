# 1.1.1

## 变更

- 判定压缩的权力归助手。例行压缩由「水位到线即压」改为三线制。`triggerRatio`（默认 25%）与 `bufferRatio`（默认 45%）只注入提示，助手把当前子任务推进到安全断点后调用 `ho_handover(action="compact")` 执行压缩。只有 `hardRatio`（默认 60%）由插件强制压缩，这是插件侧唯一的压缩路径。
- 25% 与 45% 使用同一句式提示，只改可延续上界。同一会话同一档位只注入一次，压缩成功后重置。提示与轮首水位都追加在末尾，不改系统提示头，不逐步注入。
- 新增助手执行入口 `ho_handover(action="compact")`：轮内调用宿主压缩引擎的 `compactRegion`，零可见消息，不需授权。前置校验为 3 项：交接在本次提示之后写入、无未闭合工具调用、无排队或进行中的压缩。任一项不满足即拒绝并如实回告。
- 压缩成功后注入一条上下文起点。该起点取交接的下一步、已确认事实与指针，附交接文件路径。总长不超过 400 字。
- 换任改为独立机制。每次压缩成功计数加一，助手触发与强制压缩都计。达到 `maxCompactionsPerSession`（默认 3）即提示换任。换任按 4 步执行：读旧交接、归档并核对 sha256、读模板、新建写入。6 道硬闸全部通过且用户授权有效，才建立接任会话并登记在任。
- 宿主没有清空上下文的应用程序接口（API）。压缩必然留下摘要节点，因此不做同会话压缩式清空，也不用压缩冒充换任。
- 会话级产物（微快照、回填记录、提示状态、段索引缓存）改存会话目录内 `<sid>\dsh-handover\`，与会话日志同目录。会话目录被删除时随之消失；插件未加载、未运行也成立。旧位置数据在下次写入时迁入。
- `anomalyDelta` 停止参与水位判定，其语义由缓冲线承担；「连续 2 次压缩后水位不回落」保留为追加提示理由。`hardRatio` 保持 60%，`retainTokens` 标注为尽力而为并在压缩日志中记录实际保留量。

## 工具面收敛

工具面由 14 个 `ho_*` 与 `peer` 收敛为 6 个 `ho_*` 与 `peer`。每个入口按「一次要做的一件事」合并，动作用 `action`、视图用 `view` 分流；旧工具名不再注册。

| 入口 | 覆盖能力 |
|---|---|
| `ho_status` | 水位、简报、自检、漂移、token 体检，以及闸门与交接体检（`view="gate"`） |
| `ho_handover` | 交接读、新建、写入、追加、归档，以及轮内压缩（`action="compact"`） |
| `ho_docmap` | 体系注册（`registry-*`）、行动计划（`plan-*`）、骨架（`profile-*`）、台账（`changelog-append`）、规则正文（`rules-read`） |
| `ho_sessions` | 清点、角色、建会话、指令、归档，以及在任登记（`office-read`、`office-register`）与换任（`succeed`） |
| `ho_workspace` | 工作区生命周期、全局根目录迁移，以及备份与迁移包（`backup-*`） |
| `ho_recall` | 压缩前原文召回 |
| `peer` | 平级会话通信 |

角色可见性不变：全局可见 6 个入口与 `peer`。项目与杂项看不到 `ho_workspace`，`ho_sessions` 仅开放 `succeed`。普通会话不加载工具，也不注入提示段。

## 参数与校验

- 每个入口只列本动作相关字段，参数说明不超过 40 字。
- 必填参数在分发处校验；缺失时按「现象、原因、处置」返回，不进入业务分支。
- 写入类动作沿用原有备份、预演与角色限制。

## 兼容性

旧工具名一律不再注册，调用会得到未知工具提示；按上表改用新入口与动作即可。`ho_handover(action="checkpoint")` 已移除，提前压缩改用 `action="compact"`；交接级重置改用换任流程。

## 迁移

已把宿主 `compaction-basic` 的 `thresholdRatio` 覆盖到 25% 的 profile。该覆盖应删除，并重启 DeepSeek Harness（DSH）。此后由插件按三线制提示，宿主阈值回到 0.8。旧快照目录里的会话级产物会在下一次写入时迁入会话目录内。
