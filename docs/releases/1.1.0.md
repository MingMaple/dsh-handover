# 1.1.0

**本次修改**：机制规则改为随插件本体分发，部署不再向工作区铺副本。对齐检查新增「遗留机制规则副本」分组。对外文档一并完成措辞复查与重写。

**状态刷新**：建议。新口径须落到工作区后才生效。升级后点击一次「对齐检查」，它会列出工作区里既有的 6 份机制规则副本。逐份给比对结论，获得选择后才处置。

## 新增

- 版本 1.1.0 起，6 份机制规则（交接、迁移、杂项、暂任、外部暂任、团队协作）随包分发，写入工作区的通道关闭。
- `ho_docmap(action="rules-read", doc="team_collab_rules")`：补齐团队协作规则的读取键。
- 对齐检查新增「遗留规则副本」分组：工作区存在同名机制规则文件时逐份列出。
- 全局任务库建立时，暂任与交接规则从内置模板复制，不再依赖工作区是否留有副本。

## 变更

- 触发索引与角色提示由工作区绝对路径改为 `rules-read` 的 doc 键。工作区放同名文件时仍优先，作为本地化覆盖。
- 部署清单只写章程骨架与模板骨架；`_Control_Center/user` 目录不再代建。
- `Align_Check.md` 第 7 项改为「机制规则归属」，§3 增第 8 项「遗留机制规则副本」。删除口径为：先列清单，逐份报比对结论，获选择后才执行。
- 提示段与手册的规范指针改为通用表述：只写目录约定、入口文件与查找顺序，不写死具体规范名。

## 修复

- 空白机器验收断言反转：由「应铺 6 份规则」改为「不得铺」，并新增「不代建个人目录」。
- 自测新增 3 例：遗留副本计入缺项、判定与渲染可见。

## 移除

- `src/templates/rules/Writing_Rules.md`：个人写作口径的默认指针模板。
- `src/templates/standards/` 下 4 份个人规范模板。

## 边界

- 工作区已有的机制规则副本不自动删除；由对齐检查列出后按用户选择处置。
- 不写项目库内文件；不改宿主配置。
