# 0.9.12

本次更新：首次安装改为一键部署；修「设置角色后必须重启 DSH」，并把角色装配收敛成一条主线；新建会话必须指明工作区。

## 新增与调整

- 一键部署：在设置页「首次安装」卡片粘贴绝对路径后点击「一键部署」，一次完成三件事：建立 `_Workspace` 与整套文件结构，把该目录注册为「全局」工作区，新建一个「全局」会话并登记全局角色。「全局」会话的产生不再依赖手工新建标题含「全局」的会话。
- 补建入口：工作区已接入但还没有全局会话时，设置页单独出现「全局会话」卡片，可随时补建；只建会话，不建体系，不动既有文件。
- 新建会话必须指明工作区：`ho_sessions(action="new")` 未给 `workspace` 或 `cwd`、或项目没有对应工作区时直接报错，并列出已注册的工作区，不再静默落到调用者所在的工作区。传 `project` 且存在同名工作区时自动匹配；`cwd` 必须是已注册工作区的根。
- `ho_workspace(action="create")` 新增 `ensure`：目录不存在时自动创建再注册。仍是显式开关，默认不建目录。

## 修正

- 设置角色后必须重启 DSH 才生效：此前角色装配散在三套机制上——每步条件只排子会话、角色裁剪另用 `restrict`、角色表晚到再靠 1.5 秒与 4.5 秒的延迟复核。会话休眠期间改了角色，唤醒时宿主不保证重发创建事件，`restrict` 没有机会撤销，工具仍是旧的。现在收敛为一条主线：工具可见性由每步启用条件算，角色判定用 2 秒短缓存、写角色表即失效；提示段由创建、开轮前核对与重载补装三处对齐；只有不支持按步解析的旧内核才退回 `restrict`。
- 角色查找增加一层兜底：按会话 id 无法取到活体时，再按会话头的 id 在活体列表中查找，避免把仍在内存中的会话误判为已休眠。
- 删除不再使用的旧逻辑：延迟复核、一次性引导状态、重复的会话投递与建会话代码、未使用的辅助函数。会话投递与建会话各收敛成一个共用入口。

## 升级

- 从 npm 或 GitHub 安装后启用插件；已安装旧版时先停用再换版本，安装完成后启用并重启 DSH 一次。
- 以本地 `dist/` 挂载的安装方式：替换 `dist/` 后在插件列表停用再启用即换用新代码，不必重启 DSH。
- 升级后已有的角色与交接无需迁移。已存在的会话若仍显示旧提示段文本，重启 DSH 一次即可换成新文本，工具裁剪不受影响。

## 兼容

- 支持 DSH 内核 0.2.1-rc.2 至 0.3.0，不含 0.3.0 及其候选版，见 `package.json` 的 `engines.dsh`。
- 首次实机安装建议先在空环境演练一次。
