# 0.9.13

本次更新新增两项能力：查询当前在任的会话，以及由会话在用户同意后自行完成换任。换任不再需要由全局会话代为办理；建立新会话时会同时写入在任记录。

## 新增

- 在任登记：每一类会话（全局、各个项目、各个杂项任务）都在 `_Control_Center/records/Office.json` 中记录当前在任的会话与历代编号；新的编号按该类已用的最大编号加一分配。`_Project_Meta/Registry.md` 中的「在役会话」一列由插件填写，只改这一格，其余文字不动。
- `ho_office`：查询某一类会话当前由哪个会话在任，返回名字与会话 id。可以输入不确定的名字（例如「全局3」会返回现任全局），多个名字用空格分隔，留空则列出全部；`json=true` 返回可供程序处理的结果。
- 命令行 `node scripts/office.mjs 全局 全局3`：与 `ho_office` 使用同一份实现与同一份记录，不启动会话即可查询；支持 `--root` 指定工作区根、`--all` 列出全部、`--json` 输出 JSON。
- `ho_succeed`：在任会话在用户授权后自行完成换任。依次校验授权、交接内容与在任身份，按记录分配新编号，建立接任会话并写入角色，登记在任，投递启动提示词，在旧交接末尾追加换任登记，最后注销本次授权。
- 换任授权：聊天框命令 `/allow-succeed`，或设置页「压缩授权」卡片内的「换任授权」区域。一次有效，5 分钟内可用，按会话生效；与压缩授权分别记录，互不影响。

## 改动

- 换任改由会话自行办理：由在任会话自己执行，不再由全局会话转交；全局的建会话与换任能力保留，作为自动流程失败时的备选方案。
- `ho_sessions(action="new")` 建立会话后自动写入在任记录，原在任者转为历史记录；全局手动建立会话不再漏记。
- 工具数量按角色调整：全局 24 个，项目 11 个，杂项 11 个，普通 0 个。
- 工作区规则同步：`Workspace_Charter.md` §7.2.8 为换任流程，§7.2.3 中的扫描与通知流程停止使用。

## 修复

- 修复换任需经全局会话转交、全局繁忙或休眠时换任停滞的问题。
- 修复全局手动建立会话后，在任记录与实际状态不一致的问题。

## 说明

- 换任有三项限制：只按会话自身已登记的角色确定它属于哪一类会话，不采用调用时传入的参数；只有该类会话当前在任者本人可以换任；已交接的旧会话不得再次换任。
- 交接内容检查只看结构：包含「下一步」一节且至少有一个条目，内容非空，且不含模板占位符。任何一项不通过时，整体不做任何改动，并逐条列出缺项。
- 换任授权与压缩授权分别记录，一种授权不能替代另一种；授权使用后即失效。
- 升级不需要迁移数据，已有交接无需改写。首次登记后，插件在工作区生成 `Office.json`。
