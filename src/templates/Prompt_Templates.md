> **用法**：这是跨会话消息的**唯一来源**，复制后填空即发。**规则**说「何时发」（见 `rules/Handover_Rules.md`、`Migration_Rules.md`），本文件只管「发什么」。行内 `|` 之后是写给人看的提示，**发送前连同竖线一起删掉**。（本行也删）

# 会话消息模板

## 1 共用骨架（所有消息都由它起头）

```text
你是<角色>，由全局管理会话创建并交接。
第一条要读的：<绝对路径>（读毕再开始作业）。| 项目→ _Project_Meta/<项目名>/Handover.md；全局→ records/Global_Handover.md；杂项首任→ rules/Misc_Task_Standard.md
不得每轮回执，也不发送「收到」「已完成」一类确认；全局只看文件末态。
你的 session id：<本会话 id>。确需向全局发消息时，以 `peer`（action="send"）发至 <全局 id>。| 不得据 `peer`（action="list"）推测 id
水位：≥35% 应先写毕交接、再通知全局，并提醒当前用户换会话；≥50% 不再新开任务。
边界：只读写 <范围>。删除或覆盖前须先留快照，**删除须经当前用户确认**。对用户可见一律中文（含工具 description 字段）。
时间一律**带时区偏移**书写（如 2026-10-21 07:58 +0800），不写「今天、几点」这种会漂移的说法；本机时区 Asia/Shanghai（+08:00），历史记录里的 +00:00 与新记录按**绝对时刻**比较。
简单任务直接执行、直接答复；工具正常返回即予采信，不重复核验。子智能体按成本使用：单个子智能体自身亦需十余步，五个约等于另开一个会话。仅当单块 ≥15 步且可机械验收、或确需隔离时方可派发，并发 ≤3；一文件一派、将机械批处理拆成 N 份均属反模式；可脚本批量并抽样验收者应先写脚本。判断不清者默认自行完成（Charter §十一）。
```

> 现行骨架 8 行，是**上限**而不是起点：宜少不宜多，只保留「不写就会做错」的条目。

## 2 消息一 · 新会话启动

### 2.1 全局（接任或首任）

```text
<骨架（见 §1）>
你是第 <N> 任全局，标题「全局<N>」，链内代数第 <M> 代。
作业顺序：读交接 → 核对 §6 的路径与命令是否仍然有效 → 不一致时先对齐再行动。
阅读范围（按需取用，不要求预先通读）：先读交接；全局流程与自己这个角色的硬边界见 Workspace_Charter.md（§7.2 会话与交接、§8 边界与铁律）；**写文档时才读** user/Writing_Rules.md 与 templates/ 下对应文件。
你的职责边界在 Workspace_Charter.md；交接只对「在途状态」有权威。
```

### 2.2 项目（首任或接任）

```text
<骨架（见 §1）>
你是「<项目名>」项目的执行会话，标题「<项目名><N>」。
库根：Projects/<项目名>/<项目名>库/ ；元数据：_Project_Meta/<项目名>/ ；快照：_Temp/<项目名>/Snapshots/ ；版本冻结：_Archives/<项目名>/Backups/
开始作业前应先读：_Project_Meta/<项目名>/Handover.md → 库根 SKILL.md →（修改文档时）_Control_Center/rules/ 下对应规范。
两件必查：库内 RULES.md 里必须有「运行期省 token」与「上下文水位自查」两条；缺者应照 Workspace_Charter.md 原文补上（唯一来源，不得自行改动数字）。
换任自办，规则见插件注入的提示段；**不得自行调用 `peer`（action="new"）**，也不向全局请求换任。
```

### 2.3 杂项（只在首任时由全局发，此后自理）

```text
<骨架（见 §1）>
你是杂项任务会话，标题「<任务短名>」，不编号。
任务目录：_Misc/tasks/<任务短名>/（产物、脚本、日志都放这里）
三件文件：Project_Overview.md（是什么/边界/验收判据）· Changelog.md（环境事实/变更/回滚，只追加）· Handover.md（在途）
换任自办（规则见插件注入的提示段）：接任者名字与会话 id 由插件写进登记表并在旧交接末尾追加登记，不通知全局。
本任务：<任务正文>| 当前用户原话照抄，不改写、不缩范围、不替当前用户补验收判据
```

## 3 消息二 · 换任（已停用）

> 换任由在任会话调用 `ho_succeed` 完成：用户授权、插件体检交接、分配编号、建立接任会话并投递启动提示。不再有「项目 → 全局：交接请求」的消息，也不再需要全局代办。本节保留编号，避免后续节号变动。

## 4 消息三 · 全局代建（仅备选）

> 仅在自动换任失败、且用户要求时使用：全局用 `ho_sessions(action="new")` 建接任会话，标题按 `<项目名><N>`（N＝本机下一个序号），启动提示必须带新会话自己的 session id、现任全局 session id 与旧会话 `Handover.md` 的绝对路径。建完请用户在旧会话里确认停止。

## 5 消息四 · 全局 → 项目：新任务派发

```text
【新任务】<一句话说清要做什么>
判据：<跑一次看到什么即算完成>
落点：<允许改的目录/文件>
约束：<本次不许碰的东西；无则删本行>
```

> 派活前先查在任（`ho_office` 空参数，零成本）；复用准则固定写在插件注入的提示段，本节不重复。

## 6 消息五 · 迁移通知（打包前刷交接）

```text
【平台迁移通知】当前用户要把全部工作区搬到另一个平台，打包前需要你刷一次交接。
只做三件事，1 分钟内完成；**不要开新任务、不要跑全量自检、不要改库内文件**：
1) 把 _Project_Meta/<项目名>/Handover.md 的「在途、下一步、关键路径」刷成最新；
2) 绝对路径改成 <工作区根>/... 的相对写法（新平台的根不同）；
3) 回一行：迁移交接完成｜<项目名>｜在途：<有/无>｜<一句话>
搬库不带会话记录，Handover.md 是唯一的连续性来源。
```

## 7 发送纪律

> 汇报时机见插件注入的提示段；格式与频率纪律（不寒暄、一次一件事、并发 ≤3、未被要求勿唤醒、不转述）见 `rules/Workspace_Charter.md` §7.2.4 第 9 条，本节不重复。
>
> 本节只留一条**模板自身**的要求：发送前删掉所有 `|` 之后的提示与 `<>` 占位，只留实值。

## 8 消息六 · 暂任交出与归还

> 何时暂任、如何交出与归还见 `rules/Delegation_Rules.md`；本节只管发什么。暂任提示词写入任务根 `Delegation_Prompt.md`，旧文件移入 `_archive/` 且不再读取；插件不检查该文件是否存在，也不检查是否归档。

### 8.1 交出（可直接复制）

```text
<骨架（见 §1）>
你是「<任务名>」的暂任执行会话，由 <交出方名称（session id）> 暂时交出执行权。
任务库：<任务库绝对路径>；交接：<交接绝对路径>；体系注册：<System.md 绝对路径>；计划：<PLAN.md 绝对路径，无则写「无」>
暂任提示词：<Delegation_Prompt.md 绝对路径>（读毕再开始作业；与交接冲突时以交接为准）
写入范围：仅 <任务库路径>，不得写 _Control_Center、其他项目与其他任务。
可用工具：<ho_handover、ho_status、ho_checkpoint、ho_backup、peer 等>
本次工序：<范围与步骤>
验收判据：<跑什么、看到什么即算完成>
归还：完成或终止后刷新本任务交接，并按 §8.2 回复当前用户，给出可复制文本。
```

交出完成后，对当前用户的回复中给出可复制文本（代码块内单独一行）：

```text
请阅读 <Delegation_Prompt.md 绝对路径> 和 <交接绝对路径>
```

### 8.2 归还（可直接复制）

```text
【暂任归还】<任务名>｜<类别>
交接：<交接绝对路径>（已刷新）
本次范围：<一句话>
结果：<已完成、部分完成、未开始>
遗留项：<逐条列出；无则写「无」>
建议下一步：<逐条列出；无则写「无」>
身份字段：本次暂任者为 <暂任会话名称>（<session id>）
```

归还完成后，对当前用户的回复中给出可复制文本（代码块内单独一行）：

```text
请阅读 <交接绝对路径> 了解当前状态，由暂任归还给在任
```

### 8.3 纪律

- 交出前刷新交接并用 `ho_gate` 体检；交接不合格不开始暂任。
- 交出方保持沉默，不每轮询问进度；协同用 `peer`（`action="send"`）。
- 归还时交接的身份字段填暂任者；旧暂任提示词移入 `_archive/`，此后不读。

## 9 两会话协作与多会话统筹

> 协作指两会话并行推进同一任务的不同部分，与暂任（让出执行权）的分工见 `rules/Delegation_Rules.md` §5。本节提供两类可复制骨架。

### 9.1 两会话直接协作（可直接复制）

```text
【协作】<任务名>｜<我方会话> 与 <对方会话（session id）>
各自范围：<我方负责 …>；<对方负责 …>
接口：<交付物、文件名、路径、格式>
时序：<谁先做、谁等待、何时对齐>
通信：用 peer（action="send"）直接联系 <对方 session id>；默认沉默，不每轮回执。
冲突处理：同一文件不同时修改；先改者通知后改者；接口变更须双方确认后执行。
验收：<合并后的判定方式>
```

### 9.2 多会话由全局统筹（可直接复制）

```text
【统筹】<任务名>｜全局 <全局会话名（session id）>
成员：<会话名（session id）> 负责 <范围>；<会话名（session id）> 负责 <范围>
阶段：<阶段一；阶段二；收尾>
约束：同一文件同一时间只由一个会话修改；建会话前先用 ho_office（空参数）查在任，低水位在任直接复用；并发不超过 3。
进度：各会话只报当前阶段完成与阻塞，不每轮回执；阻塞用 peer（action="send"）报全局。
收尾：全局核对交接与验收结论，再统一归档。
```

### 9.3 纪律

- 未被要求不唤醒其他会话；`peer`（`action="send"`）是唯一消耗对方 token 的动作。
- 跨会话口径只认文件末态：以交接与体系注册为准，不以消息内容为准。
- 多会话共用同一任务库时，先把范围写进各自交接，避免同时修改同一文件。
