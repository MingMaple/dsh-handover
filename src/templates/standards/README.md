# 通用规范

本目录存放跨会话共用的文档规范。任何角色的会话都可读取；新增与改写只由全局会话执行。

## 结构

一条规范一个子目录，目录名即规范名，例如 `写作规范/`、`发布流程/`、`文档结构/`。

- 正文放在子目录内，入口文件用 `README.md`；篇幅长时拆成多份，并在入口列出清单。
- 规范自带的脚本与附件放在同一子目录内，不放进 `_Control_Center/tools/`：脚本与正文同生共死，一起搬走才不会失效。
- 规范只写做法、判据与验收条件，不写某一次作业的进度与结果；进度属于交接与台账。

### 写作规范子目录

`写作规范/` 是常设规范，随插件发布：入口为 `写作规范/README.md`，条款编号 W-01 至 W-42；同目录 `依据_论文.md` 只作追溯，不作执行文本，不注入提示段。

- 适用范围：全部会话与全部构建产出，含代码注释、提交信息、文档、版本说明、提示段、工具描述、设置页文案、错误消息、交接与台账。
- 使用方式：提示段只放一行指针，条款正文按需读取；语体门禁按该文件的条款与编号执行。
- 例外：唯一既存项为对外仓库 README 第 9 行，按该文件 §4.2 登记，不得扩充。

## 查找

用户提到「按某某规范进行」一类要求时，两处都属查找范围：先看本库有无同名规范，再看本目录。本库指会话自己所在的工作区；两处都有时按本库那份执行，本目录那份作为通用版本。

正文取到后按其中的步骤与判据执行，不自行增删步骤；规范本身需要改动时，先改规范再作业。

`写作规范/` 属常设规范，条款正文按需读取，不注入提示段。

## 写入

用户提到「把某某写成规范」时：未指明范围就写本库（该会话所在的工作区）；说「写入通用规范库」「写成通用规范」「写成共用规范」的才写入本目录。

本目录的新增与改写由全局会话执行，项目与杂项会话只读；本库内的文档由本库会话自己写。规范里的路径与工具名要与插件当时的实际口径一致，改名或换入口时同步改本目录。

`写作规范/` 的条款与编号由规范维护者改写，其余会话只读；条款编号一经分配不再复用。

目录内只有本说明是合法状态：尚无共用规范时，各库按自己的文档执行。
