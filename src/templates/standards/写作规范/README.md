# 写作规范

> 版本 1.0.0（2026-11-14）。执行口径见本文件；研究依据见同目录 `依据_论文.md`（只作追溯，不作执行文本，不注入提示段）。

## 1 适用范围

本规范约束 dsh-handover 体系全部会话（全局、项目、杂项、普通）与全部构建产出：代码注释、提交信息、README 与文档、版本说明、提示段与工具描述、设置页文案、错误消息、交接与台账、审阅材料。

规范只约束书面语的表层可控特征：用词、句式、术语、标点、数字、结构、链接与体裁要素；不涉及创意文案、市场宣传与文学表达。

## 2 原则

准确、简洁、一致、面向读者、可操作、可检验。冲突按此顺序裁决：准确优先于简洁，一致优先于修辞变化，可操作优先于句式美观，可检验优先于条款完备。

## 3 条款

检查方式分「自动」（脚本可判定）与「人工」（需语境判断）。编号一经分配不再复用；条款废止时保留编号并标注日期。

### 3.1 用词与语体

| 编号 | 条款 | 检查 |
|---|---|---|
| W-01 | 不使用口语词与语气词（吧、呢、啦、嘛、呀、哈、哦、其实、反正） | 自动 |
| W-02 | 不使用情绪化、评价性表达（完美、惊艳、糟糕、坑、丝滑、离谱） | 自动 |
| W-03 | 不以比喻、拟人替代术语（打通、收口、抓手、链路、落地） | 人工 |
| W-04 | 不使用填充语（值得注意的是、众所周知、简单来说） | 自动 |
| W-05 | 「点」一律写「点击」；界面动作统一为点击、选择、输入、按 | 自动 |
| W-06 | 不堆叠同义修饰（彻底完全、基本大致） | 自动 |
| W-07 | 不使用网络缩略语、表情符号与装饰符号 | 自动 |
| W-08 | 不使用感叹号；问号不叠用 | 自动 |

### 3.2 句式

| 编号 | 条款 | 检查 |
|---|---|---|
| W-09 | 单句宜不超过 40 字；超过应拆分，且不丢失限定条件 | 自动 |
| W-10 | 一段只含一个主题，段首宜为主题句 | 人工 |
| W-11 | 条件、前提、目的置于动作之前 | 人工 |
| W-12 | 以主动语态为主；确需强调受事时可用被动 | 自动＋人工 |
| W-13 | 控制名词化，不用「进行／实施／开展＋名词」替代实义动词 | 自动 |
| W-14 | 一句只含一个指令；并列动作分条 | 人工 |
| W-15 | 操作步骤首句含祈使动词，位置信息先于动作 | 自动＋人工 |
| W-16 | 结论前置，首句给出完整判断，不铺垫背景 | 人工 |

### 3.3 术语

| 编号 | 条款 | 检查 |
|---|---|---|
| W-17 | 同一对象在同一体系内只有一个称名，禁止同义换用 | 自动 |
| W-18 | 术语首次出现就地定义或给链接，不设集中定义章 | 人工 |
| W-19 | 缩写首次出现写「全称（缩写）」，其后统一使用缩写 | 自动 |
| W-20 | 不自造缩写，不混用中英变体 | 自动 |
| W-21 | 产品名、标准号、代码标识符保持官方写法与大小写 | 自动 |
| W-22 | 清单场景穷举，关键项不以「等」「之类」省略 | 人工 |

### 3.4 标点与数字

| 编号 | 条款 | 检查 |
|---|---|---|
| W-23 | 中文正文用全角标点；代码、路径、命令、标识符用半角并加反引号 | 自动 |
| W-24 | 并列词语用顿号，并列分句用分号，不用逗号连接并列项 | 自动 |
| W-25 | 书名号、引号、括号成对出现，嵌套不超过两层 | 自动 |
| W-26 | 计量、统计、编号用阿拉伯数字；概数与惯用语用汉字 | 自动 |
| W-27 | 版本号用 vX.Y.Z，日期用 YYYY-MM-DD，时间用 24 小时制 | 自动 |
| W-28 | 标准号写全，含编号、破折号与年号（如 GB/T 15834—2011） | 自动 |

### 3.5 结构、链接与引用

| 编号 | 条款 | 检查 |
|---|---|---|
| W-29 | 每份文档只有一个一级标题，标题层级不跳级 | 自动 |
| W-30 | 标题不带句末标点，不以编号充当层级，标题内不放链接 | 自动 |
| W-31 | 标题与内容对应，无空标题，无标题与正文错位 | 人工 |
| W-32 | 链接文字自述目标，禁止「点击这里」「详见」「此处」 | 自动 |
| W-33 | 外链可解析，去除追踪参数，优先一手来源 | 自动＋人工 |
| W-34 | 正文引用编号与参考文献条目一一对应，不得悬空 | 自动 |

### 3.6 场景专项

| 编号 | 条款 | 检查 |
|---|---|---|
| W-35 | 代码注释解释「为什么」，不复述语句行为 | 人工 |
| W-36 | 文档注释含摘要、参数、返回值、异常与副作用 | 自动 |
| W-37 | 提交信息首行不超过 50 字符，用祈使式，空行后写正文 | 自动 |
| W-38 | 版本说明按新增、变更、修复、移除、安全分组，每条一句 | 自动 |
| W-39 | 错误消息含现象、原因、处置三段 | 自动＋人工 |
| W-40 | 交接文档含状态、已完成、未完成、风险、下一步、路径六项 | 自动 |
| W-41 | 台账一行一事实，字段固定，状态取受控词表 | 自动 |
| W-42 | 规范性关键词全大写且仅用于契约语义；中文对应「应／宜／可」 | 自动 |

## 4 执行

### 4.1 三道门禁

1. 生成时自检：产出文本后、写入文件前检查阻断级条款，命中即改写。
2. 提交时检查：脚本对暂存内容执行全部自动条款；阻断级违规拒绝提交，警告级写入报告。
3. 评审时复核：逐项确认人工条款，并对警告项给出处置意见。

三道门禁共用本条款表与编号。门禁配置与规范同版本发布。

### 4.2 分级与例外

- 分级：「应」为阻断，「宜」为警告，「可」为提示。
- 例外登记七项：编号、条款、适用路径、理由、替代措施、批准人、生效期与复核日。例外绑定具体路径，不得全局豁免，到期未复核自动失效。
- W-01 至 W-08 属阻断级词表，不得登记例外。
- 唯一既存例外 E-01：插件对外仓库 README 的「为什么需要」一节（`README.md` 中 `## 为什么需要` 至下一个 `##` 之间，含「本插件一定能很好地帮助你。来试试吧；不满意，随时关闭插件并删除即可。」）。用户 2026-11-13 与 2026-11-15 两次指定保留；按节绑定，不按行号；`check-docs` 逐字比对，改写即失败。

### 4.3 版本化

语义化版本：主版本变更指条款增删或判定标准改变；次版本指措辞澄清或阈值调整；修订版本指笔误与格式修正。编号永久保留，废止条款标注日期与替代条款。规范文本、条款表、门禁配置与评审清单同版本发布；不一致时以本文件为准。

### 4.4 提示段

所有角色提示段只放一行指向本文件的指针，不注入条款正文；规范正文按需读取。

## 5 依据与限制

条款依据为 `依据_论文.md`：国际风格指南（Microsoft、Google）、简明语言标准（ISO 24495-1:2023、Digital.gov）、使用说明标准（IEC/IEEE 82079-1:2019）、代码注释规范（Go、PEP 257、JSDoc、Oracle JavaDoc、rustdoc）、中文国家标准（GB/T 15834、15835、7713.2、8567、1.1）与规范性关键词（RFC 2119、RFC 8174）。

取证限制：Google 指南经官方镜像 developers.google.cn 取得；中文国标多仅公开题录，相关论断限定在适用范围层面；ISO 24495-1 与 IEC/IEEE 82079-1 全文付费，仅依据官方摘要页。W-09 的 40 字与 W-37 的 50 字符为工程设定值，非标准规定，调整须记入变更记录并同步门禁配置。
