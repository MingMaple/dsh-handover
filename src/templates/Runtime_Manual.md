# dsh-handover 运行期完整手册

> 这是**按需取回**的全文：系统提示里只留短段与指针，需要细节时用 `ho_charter(doc="runtime")` 取本文。
>
> **内置即默认**：本文、Charter 骨架、交接、台账骨架、提示词模板、四份规则文档都随插件发布（`dist/templates/`）。工作区里的同名文件只是「本地化覆盖」；删掉就自动回到内置，功能不降级。`ho_workspace(action="init")` 是把默认口径写入磁盘，便于修改，**不是使用前提**。
> 口径冲突时以工作区的 `_Control_Center/rules/` 为准；本文只讲「插件怎么用、角色怎么分」。

## 1. 角色四档

| 角色 | 判定顺序 | 交接文件 | 可见工具 |
|---|---|---|---|
| 全局 | 角色表 → 标题含「全局」 → 全局工作区 | `_Control_Center/records/Global_Handover.md` | 14 个（全部） |
| 项目 | 角色表（带项目名）→ cwd 在 `Projects/<名>/` → 首条提示含 `Projects/<名>/` | `_Project_Meta/<项目>/Handover.md` | 11 个 |
| 杂项 | 角色表（带任务名）→ cwd 在 `_Misc/tasks/<任务>/` | `_Misc/tasks/<任务>/Handover.md` | 10 个 |
| 普通 | 子会话，或都不中 | 无（不参与交接） | 0 个（不注入提示段） |

角色表在 `~/.dsh/storages/dsh-handover.roles.json`，是**本机状态**，不进仓库、不进迁移包。子会话默认普通；需要时由全局在角色表里指定。
设定入口：设置 → dsh-handover →「会话角色」；或对全局说「把 Demo1 设成项目角色」，它用 `ho_sessions(action="role")` 办。

## 2. 工具清单（14 个）

### 只读
- `ho_status` —— 会话状态，`view` 分流：`phase`（缺省；水位、压缩次数、锁、建议动作，并列出当前授权）、`brief`（起始简报：水位、闸门、会话清点、漂移、阶段建议）、`diag`（插件自检：服务、调度器、初始化错误、角色与工具集）、`drift`（交接漂移：Δ＝当前轮−交接轮，>3 需刷新）、`tokens`（token 体检，需 `sessions`）。
- `ho_gate` —— 通用约束条闸门（按骨架档案的库型判定）＋交接文档体检＋文档定位 map 的路径检查。
- `ho_sessions` —— 会话清点；也用来设定角色、建会话、出提示词、归档、解归档（`action` 分流）。
- `ho_charter` —— 按节取规则正文：`doc`＝`charter`（缺省）、`handover_rules`、`migration_rules`、`misc_standard`、`writing_rules`、`runtime`（本文全文）；`section` 留空只列目录。**工作区没有对应规则文件时退回插件内置默认口径**（输出会注明），所以换到空白机器也不会变空壳。
- `ho_office` —— 查在任：输入「全局」「全局3」「项目名」等，返回现任会话的名字与会话 id；多个名字空格分隔，留空列出全部。
- `ho_docmap` —— 本血脉的文档定位：`action=read|write|check`。血脉由本会话角色推导，不接受传入项目名；写入者必须是该血脉在任者，已交出的旧会话只读。

### 写
- `ho_handover` —— 读、写、追加、归档**本会话自己的**交接（写前自动备份、写后按角色体检）。
- `ho_checkpoint` —— 写交接 → 体检 → 登记压缩 → 轮末自动压缩。`resume=continue`（缺省）压缩后续跑；`resume=wait` 表示任务已收尾，压缩后不唤醒。
- `ho_changelog` —— 按固定表格追加一行台账。
- `ho_backup` —— `action`：`snapshot`（缺省；库快照，逐字节复制、sha256 清单、来源说明）、`check`（打包前置闸门）、`pack`（打包）、`verify`（校验包是否仍是现版）、`restore`（默认预演，覆盖前备份，从不删除目标文件）。`format=auto|7z|tar`：有 7-Zip 出 `.7z`，没有就出 `.tar.gz`（内置归档器，功能等价）。
- `ho_workspace` —— `action`：`init`（首次安装：在指定目录下建整套全局文件体系，可顺带注册工作区）、`list`、`create`、`delete`（删除只删注册）、`move-*`（搬迁全局根目录）。
- `ho_profile` —— 项目或杂项的骨架注册：由所属会话通读自己的库后写入并校验。
- `ho_succeed` —— 换任：用户授权后校验交接、按记录分配编号、建立接任会话、登记在任并投递启动提示词。

### 平级会话
- `peer` —— `action`：`send` 投消息（唯一消耗对方 token 的动作）、`status` 单会话详情、`list` 一览、`peek` 近期对话（耗本会话 token）、`rename` 只改标题、`new` 新建。`list`、`peek`、`rename` 仅全局可用；`send`、`status` 各角色可用；`new` 全局可用，杂项可建到 Misc 下。

### ho_sessions 的 action
| action | 作用 | 关键参数 |
|---|---|---|
| `list`（缺省） | 会话清点 | `limit`、`warn`、`include_subagents` |
| `role` | 设定会话角色（写角色表＋当场收窄＋可选投整理指令） | `session_id`、`role`、`project`、`task`、`notify` |
| `new` | 建下一代会话并唤醒，自动投启动提示词（按接任者角色取**接任者自己的**交接路径） | `title`、`workspace`、`cwd`、`message`、`project`、`force` |
| `order` | 远程给某个会话下指令：`order=handover` 让它写交接再换任；`order=compact` 给它排压缩（目标必须在内存、要有合格交接、未压满） | `session_id`、`order`、`resume`、`extra`、`force` |
| `prompt` | 按 `templates/Prompt_Templates.md` 渲染可粘贴的启动提示词 | `kind`、`project`、`title`、`sessionId`、`globalSessionId` |
| `place` | 把已存在的会话移进工作区（会话 cwd 必须正是该工作区根） | `session_id`、`workspace` |
| `archive` | 归档会话（相当于图形界面的删除） | `session_id`、`force` |
| `unarchive` | 解除归档 | `session_id` |

## 3. 水位与交接协议

- 32% 提醒、35% 交接线、85% 硬顶；同一会话最多压缩 3 次（共 4 段使用）。数值来自 `config.mjs`，提示段与设置页由 `lib/facts.mjs` 统一渲染。
- 到线流程：`ho_handover` 写交接（体检不通过就拒绝压缩）→ `ho_checkpoint` 登记（`resume=continue|wait`）→ 轮末自动压缩 → 继续时投续跑消息；收尾时不唤醒，等用户派新任务。
- 第 4 段到线或压缩额度用尽：由在任会话自己换任——写交接 → 请用户在聊天框敲 `/allow-succeed` 授权 → 调 `ho_succeed`（校验交接、分配编号、建立接任会话、登记在任、投递提示词）。全局仍可用 `ho_sessions(action="new")` 手动建立会话，作为自动流程失败时的备选方式。
- 关键步骤不要压：`ho_checkpoint` 传 `at_risk=true`，它只提醒不压；硬顶 85% 除外。
- 压缩不可逆：历史会被摘要替换，所以「先把交接写合格」是硬前提。
- 在任登记表由插件维护：`_Control_Center/records/Office.json` 记每一类会话的现任与会话 id；查现任用 `ho_office`，不起会话时用 `node scripts/office.mjs 全局 全局3`。

## 4. 交接文件的结构要求

- **全局**（`_Control_Center/records/Global_Handover.md`）：必须有 §0 身份与寻址（含 7 个字段）、§1 正在做的事、§2 下一步、§3 待用户决定（早期文档沿用旧标题，亦判通过）、§4 用户要求逐条落位、§5 坑点与禁区、§6 关键路径、§7 会话 id 对照（至少一行带 session id，且不能有「待回填」）；不得残留模板占位符。
- **项目、杂项**：必须有「正在做的事」（空节不算，只判有无实质内容，不设字数下限）、「下一步待办」（至少一条表格行或列表项）；不得残留占位符。
- 体检命令即工具：`ho_gate`（全部）、`ho_handover` 写后自动体检。
- **交接类文档不设体积上限**（不规定字节、行数、页数）：体积由结构（只写在途与指针）、书面语与归档整篇重写控制；删减依据是「过期即删」，不是「太长就砍」。

## 5. 派发与成本纪律（判据来源 Charter §十一）

1. **先核算成本**：每个子智能体都是一个完整会话——自带系统提示与任务提示，自身亦需十余步，结论还须回主会话再审读一遍。实测一次「分模块清理注释」派 5 个，各自占用 16%–20% 上下文，合计约等于另开一整个会话。
2. **三条判据全部满足方可派发**：① 单块 ≥15 步或需读 ≥10 个文件；② 确需隔离或并行等待；③ 结果可机械验收（能以一句「通过、不通过」判定）。任缺其一即应自行完成；判断不清者亦自行完成。
3. **反模式（禁止）**：一文件、一模块、一函数一子智能体；将机械批处理拆成 N 份（注释清理、逐文件润色、重命名、格式统一、补全文档）；先派发再拟定验收标准；同一任务并发超过 3。
4. **优先「脚本 + 抽检」**：可脚本批量处理、再抽 3 个样本目视检查者，一律先写脚本。子智能体仅用于无法脚本化的判断。
5. **派发前先报预算**：以「拟派 N 个子智能体，每个 ≤M 步」的形式告知用户；N>3 或合计超过一个会话的量时，须先征得用户同意。
6. **续用优先：工序延续不另行建立会话**。子智能体完成后仅转入静止状态（inactive），其对话、已读文件与既定选择均予保留，一次 `send_message` 即可继续。因此**同一批文件的下一道工序**——改尺寸、换文案、出占位版、补变体、修一处细节——必须交回**原作者**，不得另行建立子智能体。另行建立等于令新会话重读同一批文件、重新推断结构，无异于将上一轮的上下文再购置一遍。
   - 检索既有子智能体：以 `list_agents`（仅列直接子项）确认其状态为 inactive，并对照其上一轮交付的文件清单决定派发对象。
   - 续用消息宜简：说明工序、给出脚本或约束、列出文件清单即可，不必重述背景——对方保有原上下文。
   - 仅在三种情形下方可另行建立：原作者上下文将满；新工序与其产物无关；需要**独立复核**其结论（此时应刻意改派他人，并声明属复核）。

## 6. 给项目会话发提示词的硬要求

- 必须以 `_Control_Center/templates/Prompt_Templates.md` §1 共用骨架起头，保留「默认沉默·三种时机」那一行。
- **不要索要回执、不要写「每轮报告」**；写完即为完成，证据看文件末态。
- 换任提示词必须带：新会话自己的 session id、现任全局 session id、它自己的交接绝对路径。

## 7. 闸门口径

- 通用约束条只在骨架档案标为 `library` 形态的项目库里强制：逐行落进该库 `RULES.md`，并有「上下文水位自查」；构建型、动画型等项目可设 `gate.libraryBlock=false`，不再套用。
- 骨架档案由各项目会话自己通读本库后注册（`ho_profile(action=register)`）；未注册时按默认骨架运行，`ho_gate` 标「待注册」，不判红。
- 有缺只**派发**给该项目会话，全局**不代写**项目库内文件。

## 8. 迁移与恢复

1. `ho_backup({action:"check", items:[...]})` 先过前置闸门（会话静止、交接到位）。
2. `ho_backup({action:"pack", kind:"project"|"task"|"global", name:"…"})` 出包，含 manifest、CHECKSUMS、MIGRATION.md 与绝对路径体检。
3. 换机：解压包 → 装插件 → `ho_backup({action:"verify", pack:"<包>"})` 看是否仍是现版。
4. `ho_backup({action:"restore", pack:"<包>", dry_run:true})` 预演，确认后 `apply=true`。
5. **会话本身不迁移**：跨机连续性只靠交接文档。

## 9. 设置页与搬迁

- 设置页数据走**宿主认证的 `/api` 载体**（`/api/dsh-handover`），旧 HTTP 路由只作回退；页面里裸 fetch 在本机 GUI 上会被 403 挡掉。
- 换盘四步：`ho_workspace(action="move-probe", to=…)` → `action="move"`（复制并逐文件 sha256 校验）→ `action="move-switch"`（派后台助手，退出 DSH 后自动完成改名与建链接；也可双击生成的 `dsh-handover.move.cmd`）→ `action="move-cleanup", confirm=true`。
- 切换后原路径成为指向新位置的链接（Windows 为 junction，Linux、macOS 为符号链接），注册表、profile 与会话工作目录均无需修改；回退方式为删除链接、并将 `.old-*` 改回原名。
- 切换必须在 DSH 退出后执行：源目录在 DSH 运行期间被占用，目录改名与建立链接均会失败。

## 10. 硬规定

- 对用户可见的一切一律中文（工具 description、选项、清单、表格状态词都算）。
- 时间一律带偏移书写：`2026-10-23 21:40 +0800`。
- 不虚构、不越权、不擅自删除；项目库内文件只由该项目会话自己改。

## 11. 首次安装与工作区

- 两个入口**等价**：设置页「首次安装」（粘贴已存在目录 → 建立全局文件体系 → 注册为工作区）；或在对话里执行 `ho_workspace(action="init", parent=…, register=true)`。
- 未接入工作区时，闸门、交接体检、会话水位三项无数据；插件本体仍可用。
- 注册工作区亦可单独执行 `ho_workspace(action="create", path=…, title=…)`；删除只删注册，目录与日志不动。
- 项目与杂项接入后先读自己的库，再写 `project.profile.json`、`task.profile.json` 并 `ho_profile(action=register)` 注册骨架。
- 会话标题规范（全局、项目、杂项）见工作区 Charter §6.2；新建会话必须当场给标题。

## 12. 提示词预算与增删规则

### 12.1 分层（谁在每轮付费）

| 层 | 内容 | 何时进入上下文 | 实测参考（加权 token） |
|---|---|---|---|
| L0 常驻 | 角色段（全局五节；项目、杂项各节） | **每一轮** | 全局约 385；项目与杂项约 370；长路径与迁移提示档约 435、419（参考值，不设上限） |
| L0 用户内容 | 全局前置提示词（用户开关，默认关闭） | 开启且非空时每轮 | 由用户自管，不计入本插件预算 |
| L1 手册 | 本文件 | 按需取回，可**按节**取 | 不设上限（不进每轮） |
| L2 规则文档 | 工作区 `_Control_Center/rules/` | 按需 | 由工作区自管 |

> 加权 token 的算法：CJK 与全角标点每字符 1 token，其余每 4 字符 1 token。实测常量在 `lib/facts.mjs` 的 `TOKEN_BUDGET`，冒烟只打印实测值，**不设上限**，也不用于拒绝或截断。
>
> L0 是成本主体：它按轮次乘算，所以只放「每轮都要用到的判定」。任何「一个会话生命周期里只用几次」的流程，一律以指针落到 L1。

### 12.2 布局（改动必须落在既有骨架内）

- **全局段**：五节固定——身份、权限、节奏、交接、按需取用。
- **项目、杂项段**：九行固定——写入范围、库根、骨架、临时与归档、交接、水位与压缩、对外通信、指针；有迁移时另加一行。
- **普通段**：不注册任何提示段。
- 新增内容先在既有节内找位置；找不到位置，说明该内容属于 L1，而不是新增一节。

### 12.3 准入四条（进 L0 的门槛）

1. **每轮都要用到的判定**才可进 L0；有明确触发时机的一次性流程，一律写指针。
2. 同一规则**只写一处**；由所在节表达作用域，不靠重复强调。
3. 进 L0 必须指明所属节；无法归属则不进。
4. 每句都须回答：能否换成指针？不能替代的理由是什么（写入 CHANGELOG）。

### 12.4 增删流程

- **增**：判定是否每轮需要 → 若否，写进 L1 并在「按需取用」加一行指针 → 若必须进 L0，指明节次 → 跑 `blank-smoke`（体积与结构断言）→ CHANGELOG 记「加了什么、为什么不能是指针、体积变化」。
- **删**：先查引用（冒烟断言、手册同项、其他角色段）→ 同步删除 L1 与 L0 的重复表述，避免「常驻删了、文档没补」→ 再跑冒烟。
- **改**：一次改一件事；改完对比体积并记录参考值，不设上限（提示词效果优先）。

### 12.5 检查清单（每次动提示词后照着过）

1. 体积：只记录实测参考值（全局与项目段各约 400 上下），不判上限。
2. 结构：全局五节、项目九行各出现一次，顺序不变。
3. 一处一规则：会话间通信规则、压缩授权、交接线各只出现一次。
4. 禁止回灌：工作流细节（`ho_backup`、`move-probe`、具体命令步骤）不得出现在 L0。
5. 手册同步：凡 L0 指向的 section 必须在本文中存在且标题可匹配。

> 结构护栏由测试执行（节次齐全、只出现一次），不靠自觉；体积只测量、不判失败。

## 13. 文档定位与授权提示

### 13.1 文档定位（docmap）

- 每个血脉一份文件：`_Control_Center/records/docmap/global.md`、`project-<项目名>.md`、`misc-<任务名>.md`，随工作区迁移。
- 三列：路径（工作区相对路径）、一句话介绍、什么时候该读。只指路，读不读由会话自己判断，不要求通读。
- 写：`ho_docmap(action="write", entries=[…])` 整份替换，逐条校验路径存在，缺项整条拒绝；写入者必须是该血脉在任者（以 `Office.json` 为准），已交出的旧会话只读；全局不代写项目与杂项的 map。
- 生效：写盘后当场重装该会话提示段，下一轮即注入；空 map 不注入；不设字数上限。
- 闸门：`ho_gate` 检查所有 map 的路径存在性，失效即报，由该血脉在任会话更新。
- 外部承接：`_Control_Center/templates/External_Takeover_Prompt.md` 生成提示词时，把本项目 map 的表格原样嵌入「文件地图」之后并保留判定句；没有 map 则省略这一段，不得编造。

### 13.2 授权提示（压缩、换任）

- 授权由用户产生，写入 `~/.dsh/storages/dsh-handover.consent.json`，5 分钟、一次性、按会话。
- 授权一到，目标会话的提示段立刻多一行：「用户已授权<压缩|换任>，至 <时刻>（一次性，用后失效）」；过期或用掉后消失，不占位。
- `ho_status(view="phase")` 与 `view="brief"` 的输出里有一行「授权」，写明剩余分钟与到期时刻；向用户索要授权后先查它，再等回话。
- 两种授权可以并存，各占一行。
