# 写作规则（插件自带默认口径）

> 本文件只放指针与硬性要求，不复述条款表；两处冲突时以规范正文为准。

## 1 指针

- 写作规范见 `_Control_Center/standards/写作规范/README.md`（W-01 至 W-42）。
- 条款编号一经分配不再复用；检查方式分「自动」与「人工」。
- 研究依据：同目录 `依据_论文.md`，只作追溯，不作执行文本，不注入提示段。
- 提示段只放一行指针，不注入条款正文；规范正文按需读取（`ho_charter(doc="writing_rules")` 可代替本文件）。
- 例外登记唯一既存项 E-01：对外仓库 README 第 9 行，见规范 §4.2；不得扩充，改动须用户同意。

## 2 硬性要求

- 语言：对用户可见的一切一律中文，含工具描述、选项、清单与表格状态词；代码、命令、专有名词保留原文。
- 语体：标准、简洁、专业书面语。不使用口语词与语气词，不使用情绪化、评价性表达，不以比喻或拟人替代术语，不使用填充语；词表见 W-01 至 W-04。
- 界面动作统一写「点击」，不写其他同义单字（W-05）。
- 标点与数字：中文正文用全角标点；代码、路径、命令用半角并加反引号（W-23）。版本号写 vX.Y.Z，日期写 YYYY-MM-DD，时间用 24 小时制（W-27）。
- 结构：每份文档只有一个一级标题，标题层级不跳级（W-29）；标题不带句末标点，标题内不放链接（W-30）；链接文字自述目标（W-32）。
- 句式：单句宜不超过 40 字（W-09）；一个指令一句，并列动作分条（W-14）；结论前置（W-16）。
- 术语：同一对象同一称名（W-17）；缩写首次出现写「全称（缩写）」（W-19）；产品名与代码标识符保持官方写法（W-21）。
- 事实纪律：不虚构。未执行的验证不写「已验证」，未读的文件不写「已检查」；区分「已完成待验收」与「要求了未落地」。
- 交接文档六项齐全（W-40）：状态、已完成、未完成、风险、下一步、路径。
- 台账一行一事实，字段固定，状态取受控词表（W-41）。
- 错误消息含现象、原因、处置三段（W-39）。
- 规范性关键词全大写，仅用于契约语义；中文对应「应」「宜」「可」（W-42）。

## 3 时间与路径

- 时间一律带偏移（例 `2026-10-24 22:40 +0800`）；不带偏移视为缺失。
- 路径写工作区相对形式（例 `Projects/<项目>/…`），不写死本机盘符。

## 4 台账

- 结构性改动追加一行到 `_Control_Center/records/Global_Changelog.md`（`ho_changelog`）；一行说清改了什么、为什么、影响面，不复述过程。

## 5 门禁与例外

- 三道门禁：生成时自检、提交时检查、评审时复核（规范 §4.1）。命中阻断级条款即改写。
- 语体门禁纳入门禁清单；唯一豁免为对外仓库 README 第 9 行。
- 例外登记七项：编号、条款、适用路径、理由、替代措施、批准人、生效期与复核日（规范 §4.2）；例外绑定具体路径，到期未复核自动失效。
