# 交接文档规范（插件自带默认口径）

> 本文件是 dsh-handover 首次安装时铺下的默认版本，可按自己的工作方式改写。
> 插件只做两件硬事：写前备份、写后按结构体检。结构不达标时 `ho_checkpoint` 拒绝排压缩。

## 1 谁的位置

| 角色 | 交接文件 |
|---|---|
| 全局 | `_Control_Center/records/Global_Handover.md` |
| 项目 | `_Project_Meta/<项目名>/Handover.md` |
| 杂项 | `_Misc/tasks/<任务名>/Handover.md` |

各类交接不得串用：项目会话读到全局交接，等于把其他会话的状态当作自己的。

交接归属与体系注册分离：交接只写在途状态，体系注册写路径与读取时机，见 `_Control_Center/records/systems.md` 与各任务 `System.md`。

## 2 什么时候写

- 水位 35%：先写毕交接，再通知全局，并提醒当前用户换会话；此后可压缩。
- 水位 50%：不再新开任务。
- 水位 85%：硬顶，到线即压缩。
- 判断标准：35% 档要求完成剩余流程后上下文占用不超过 45%；50% 档不超过 55%。
- 压缩至多 3 次；第 4 次须换任：写交接，由用户授权后由在任会话调用 `ho_succeed` 完成换任，不得自行新建会话。
- 早于 35% 的压缩，仅限助手建议或用户主动并提出授权。

## 3 必须写清

1. 正在做什么、到哪一步：版本号、产物路径、构建是否通过。
2. 下一步按顺序：每一步写做什么、动哪个文件、完成判据。
3. 环境与路径：工具版本、安装位置、所用的源。
4. 已完成待验收与要求了未落地分开写，不混为一节。
5. 风险与禁区：已发生的问题、不得再修改的文件。
6. 会话 id 对照：在任会话、已归档的旧会话。
7. 体系注册与计划的位置：`systems.md` 或本任务 `System.md`、当前 `PLAN.md`；没有计划则写「无」。

## 4 硬规矩

- 机密只写位置，不写值：密码、令牌、证书写在哪个文件，不抄进交接正文。
- 时间一律带偏移（例 `2026-10-24 22:40 +0800`）。
- 不写「大概」「应该」这类未核过的表述；未核就写「未核，待确认」。
- 写交接用 `ho_handover(action="write")`、`action="append"`，不手工修改文件，以免绕过备份与体检。
- 归档命名：`_Archives/<范围>/Handover/<原文件名>_<YYYYMMDD_HHMMSS>.md`（例 `Handover_20261108_144307.md`）；杂项归档自包含在 `_Misc/tasks/<任务>/_archive/`。
- 篇幅不设上限：不规定字节、行数、页数。体积由结构控制——只写在途与指针、状态用表格承载；过期即删，过一段时间按归档重写。不得给交接或同类文档设上限。

## 5 体检判据（插件自动执行）

- 有标题、有「正在做的事」实质内容、有「下一步」条目、无残留占位符。
- 全局交接另需八节齐全（含 §0 身份与寻址、§5 风险与禁区、§7 会话 id 对照）、§0 七个字段齐全、§7 至少一行带 session id。
- 体检结论取「通过」「缺节」「不合格」；「缺节」允许压缩，「不合格」须补完再压缩。
- 体检命令：`ho_gate`（全局与全部项目）、`ho_handover` 写后自动体检。
