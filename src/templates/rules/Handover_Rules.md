# 交接文档规范（插件自带默认口径）

> 这份是 dsh-handover 首次安装时铺下的默认版本，可以按自己的工作方式改写。
> 插件只做两件硬事：**写前备份、写后按结构体检**；结构不达标时 `ho_checkpoint` 拒绝排压缩。

## 1. 谁的位置

| 角色 | 交接文件 |
|---|---|
| 全局 | `_Control_Center/records/Global_Handover.md` |
| 项目 | `_Project_Meta/<项目名>/Handover.md` |
| 杂项 | `_Misc/tasks/<任务名>/Handover.md` |

**绝不串用**：项目会话读到全局交接，等于把别人的状态当成自己的（0.2.x 的真实故障）。

## 2. 什么时候写

- 水位 **32%**：开始收口，别开新活。
- 水位 **35%**：必须写完交接 → `ho_checkpoint` 登记 → 轮末自动压缩 → 续跑。
- 水位 **85%**：硬顶，不压也得压。
- 同一会话最多压 3 次；第 4 段写交接并通知全局换任（**项目会话不要自己建会话**）。

## 3. 必须写清（缺一项就会在换任时丢信息）

1. **正在做什么、到哪一步**（版本号、产物路径、构建是否通过）。
2. **下一步按顺序**：每一步写「做什么、动哪个文件、完成判据」。
3. **环境与路径**：工具版本、安装位置、用的源。
4. **已完成待验收** 与 **要求了没落地** 分开写，不要混。
5. **坑点与禁区**：踩过的错、不能再动的文件。
6. **会话 id 对照**：在任会话、已归档的前任。

## 4. 硬规矩

- **机密只写位置，不写值**：密码、token、证书写在哪个文件，不要抄进交接正文。
- 时间一律带偏移（例 `2026-10-24 22:40 +0800`）。
- 不写「大概」「应该」这类没核过的话；没核就写「未核，待确认」。
- 写交接用 `ho_handover(action="write")`、`action="append"`，不要手改文件（会绕过备份与体检）。
- 归档命名：`_Archives/<范围>/Handover/<原文件名>_<YYYYMMDD_HHMMSS>.md`（例 `Handover_20261108_144307.md`）；杂项归档自包含在 `_Misc/tasks/<任务>/_archive/`。

## 5. 体检判据（插件自动跑）

- 有标题、有「正在做的事」实质内容、有「下一步」条目、无残留占位符。
- 全局交接另需 §0 的七个字段与 §7 至少一行 session id。
- 体检结论：`通过` / `缺节` / `不合格`；`缺节` 允许压缩，`不合格` 必须补完再压。
